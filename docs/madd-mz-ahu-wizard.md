# MADD-MZ AHU-only hot/cold deck wizard

Open **MADD-MZ AHU wizard** in the equipment wizard. The separately profiled `studio-madd-mz-ahu-only/1` generator creates an editable ordinary-core Program for one single-speed supply fan, separate hot-deck heating and cold-deck cooling valves, and one common mixing-damper command. Each deck has its own measured/logical temperature and adjustable fixed-target Input. Heating the hot deck while cooling the cold deck is intentional: they condition different airstreams. The existing single-SAT AHU generator and dual-duct VAV terminal wizard represent different equipment.

The first scope is **AHU Only**. It does not generate zone temperature requests, terminal dampers, zone airflow control or an unoccupied zone-minimum/maximum algorithm. Fixed targets mean no OA/RA/zone reset curve; they do not mean immutable runtime constants. The source-qualified MADD-MZ tree uses a single-speed supply fan. Generic MADD variable-fan options are a separate future profile. Return/exhaust/relief fans are absent.

Explicitly select economizer off, fixed dry-bulb or differential dry-bulb. Enabled modes require OA temperature and logical economizer permission. Differential also requires RA temperature and ordered on/off differences, plus the absolute high limit. Irrelevant fields are refused. Catalog branch defaults are supplied in both temperature units. The declared family/model/firmware/release is provenance, not verified controller allocation or native JCI acceptance.

## Inputs, commands and configuration

The nine base Inputs are occupied, unit enable, energy holdoff, independent fan proof, fan reset, hot-deck temperature, cold-deck temperature, hot-deck setpoint and cold-deck setpoint. Initial occupied, enable, fan proof and reset default false. A fan command never supplies its own operation proof. Enabled economizer adds OA and logical enable; differential adds RA.

Outputs include logical fan enable/readiness/fault, control permission, setpoint validity, independent hot-heating and cold-cooling percentages, common mixing-damper percentage, economizer availability and active-mode flags. The hot state is Boolean; authored cold-state numbers are 0 idle, 1 economizer, 2 integrated and 3 mechanical. They are not native JCI enumerations. Nominal hot-minus-cold target spread, measured hot-minus-cold spread and a nominal target-order flag are diagnostics only.

`cold_economizer_active` identifies the economizer **PI** state only. It is false during integrated operation, where the common mixing command is fixed at 100% and the mechanical PI runs. It does not report physical economizer or damper activity.

Good finite runtime deck targets outside the authored **−100 to 200 °C equivalent** range inhibit ordinary fan, valves and damper commands. Readiness, run timers and thermal states reset; inactive integrals hold. This configuration inhibition does not create a proof-fault latch. Correcting the targets requires full fan readiness again. A pre-existing proof latch remains latched.

There is **no required hot-target-above-cold-target interlock**. Equal or reversed requested targets can regulate independently. Measured hot/cold order also does not inhibit control: startup, transients or sensor locations may reverse the measured temperatures. Neither diagnostic proves deck identity, delivered temperatures or physical mixing suitability. The reset rule uses the raw occupied/enabled/not-held-off operator request, so an invalid target cannot masquerade as operator-off to reset a proof fault.

## Independent deck regulation

Hot heating enters when its measured deck is at least the declared entry difference below its own target. Its P/PI error is hot target minus hot temperature. It remains active at target with a required nonzero integral. Warm release temperature plus a low **previous committed hot command** for the declared dwell returns it to idle. Idle gates the command to zero and holds integral. There is no hot-deck cooling device.

Cold cooling enters when its measured deck is at least the declared entry difference above its independent target. Its PI error has the opposite sign: cold temperature minus cold target. Available economizer first regulates the cold deck using the larger of its demand and the position floor, with mechanical cooling zero. Warm cold-deck temperature plus a high **previous selected mixing command**, for the assist dwell, admits integrated mechanical cooling with OA command at 100%. This high test includes a 100% floor even if the economizer's demand is small.

Integrated cooling holds a required nonzero mechanical integral at setpoint. Low previous mechanical command plus cool release temperature/dwell returns to economizer. Low previous **economizer demand**, rather than the position floor, plus cool release temperature/dwell returns to idle. Unavailable economizer selects mechanical cooling at the floor; suitability returning during mechanical operation selects the authored integrated handoff. Hot heating stays independent through every cold state. A cold-deck undershoot cannot use the hot valve as preheat. Preheat is a distinct future function.

The minimum OA choice is **0–100% command position**, not outdoor-air fraction, measured airflow or ventilation. Even 100% command does not establish actuator travel, linkage, airflow or code compliance. Common mixing can affect both decks physically; this graph does not synthesize a mass/energy balance to infer those effects.

Explicit Delay nodes store previous successful commands/state for transition conditions. Current selected states gate ordinary PI outputs, so intentional feedback loops have valid state boundaries. Each active P/PI uses the unchanged core conditional antiwindup policy. Inactive loops receive their own target as measurement, giving zero error and holding integral; later reentry can restore that memory. Tracking, override reconciliation and bumpless transfer are not established.

## Fan proof and transactional quality

The operator request is occupied AND enabled AND NOT holdoff. With good configuration, fan command starts before proof. Full continuous proof time followed by full stabilization time is required before either deck or OA command opens. Startup expiry counts until readiness, including chatter. Readiness wins if it completes on the deadline scan.

After operation, good false proof immediately closes both valves and OA, while the fan may continue within the declared recovery deadline. Recovery again requires full proof and stabilization. Chatter cannot postpone expiry indefinitely. Expiry latches a fan fault; only a rising reset edge while the operator request is off clears it. A held reset cannot repeatedly retry.

Scans are whole 1–60 seconds. Positive timing choices are aligned multiples of the scan, up to 3600 seconds. Each deadline exceeds proof plus stabilization by at least one scan. Initial memory/timers are zero/false, and the first successful scan represents one declared interval. A new process starts fresh; durable field restart and power-fail persistence are not implemented.

**Bad required-input quality faults and rolls back the complete transaction**, retaining both deck outputs, fan command and all state. A same-frame false enable or lost proof does not override that rollback. Failed scans do not advance timers or consume reset edges. This differs from a good false permission or good out-of-profile target, which commands zero on a successful scan. It is also distinct from native per-module failsoft behavior and physical shutdown protections.

## Units and a known numeric boundary

F/C conversion couples all four deck defaults/targets, active OA/RA defaults and cutoffs, independent entry/release differences, differential differences and reciprocal thermal gains. Absolute temperatures use offsets; differences only scale. Kp is percent per degree and Ki is percent per degree per second. Thermal gains have a canonical Celsius-degree ceiling of 1,800,000 and sufficient raw-unit range to convert accepted F/C choices. Percentage, seconds and Boolean choices remain unchanged. No pressure conversion or variable fan is offered.

**Coupled parameters do not guarantee identical finite-precision trajectories.** Existing Python execution uses binary64 and native IEC uses REAL/float32. PI antiwindup and state thresholds are nonlinear: rounding across an exact limit can accept an integral update in one unit representation and reject it in another. That can leave a persistent command/state difference, rather than only a tiny final rounding error.

A preserved example uses hot target 85 °F, Kp 4, Ki 0.5, five active error-2 °F scans followed by target holds and two error-−1 °F scans. Fahrenheit reaches exactly zero raw PI output on the second correction and accepts the candidate integral 4. The coupled Celsius arithmetic falls slightly below zero, rejects that candidate and retains about 4.5 integral, producing about 0.5% command. Both remain in the authored heating state. Independent tests predict and assert each path. This limitation is visible and unresolved; canonical control units or unit-invariant nonlinear execution remains future work. No Engine, compiler, SDK, deadline or comparison tolerance is changed for this generator.
