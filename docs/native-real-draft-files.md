# Unfinished native Real draft files

In **Program → Native backup defaults**, open an original retained backup and
select its actual Real field. Expand **Save or import unfinished Real text**.
**Save unfinished Real draft** saves the ordinary edited text as a small JSON
file. **Import unfinished Real draft** restores that text into the same source
and field after the existing draft has been explicitly discarded.

To continue on another computer, first retain the same original native backup
using [History → Native backups → Import native backup ZIP](native-backup-import.md).
Open that source in Program, select its field and import the unfinished text.
The draft JSON contains source references and raw text; the original native
Files 3/11/12 remain in their separate backup archive.

Empty strings, incomplete decimals/exponents, negative zero, whitespace and
non-numeric text remain exact strings. Import does not evaluate, normalize or
compile them. The existing native compiler still decides whether a later
proposed value is valid. A file cannot restore a previous native review, token,
transfer confirmation, recovery proposal or current controller verification.

## Source and replacement checks

The file must match the opened capture ID, snapshot hash, capture time, Device,
complete captured target, record reference, native class/property, field encoding
hash and effective float32 bits. The ordinary source reader verifies retained
backup evidence when it is opened. Import compares against that opened source;
it sends no additional API or field request and does not assert that a retained
file or controller is still available. Every later review retains its own source
and field admission checks.

An existing ordinary field draft, including an empty string, refuses replacement.
Discard it explicitly before importing another. The existing 64-field in-memory
and browser-session budgets retain their no-eviction behavior. A full in-memory
cache refuses a new field. Browser-storage failures retain admitted text in the
open view with the existing storage warning. Importing raw text uses the same
editor and immediately retires its old native review. Refused imports preserve
existing text and a still-valid review.

Prepared previous-value proposals remain separate. The raw-file controls are
unavailable while a recovery proposal or controller operation owns the field.
Source/field/context/task changes, disclosure closing, document hiding and parent edit counters retire pending file
reads and old download handles, including changes away and back before repaint.
Late file completion cannot install text into a newer field or context.

## File profile and limits

The separate `native-real-unfinished-draft/1` profile contains only the exact
source binding and a `buffer.value_text` string. It explicitly declares
`field_authority`, `controller_queries`, `native_review_created` and
`current_identity_verified` false. Unknown fields, substituted sources, duplicate
JSON keys, invalid UTF-8/Unicode and unsupported shapes are refused.

The file ceiling is 16 KiB. Raw text keeps the editor's 128 UTF-16-unit bound.
The UI reports the imported filename and original file SHA-256 with the matching
text in that view. That message is informational; ordinary session text storage
does not become a receipt or a durable provenance database. Save the draft file
explicitly for transfer or recovery after ending a browser session.

Qualification uses authored native records and isolated source/installed
Chromium/WebKit workflows, clean browser contexts, exact raw-string round trips,
file faults, cache capacity and held/coalesced lifecycle changes. Native encoders,
field writers and styles retain their existing contracts. General native logic,
packages, native execution and physical/Bluetooth acceptance remain separate.
