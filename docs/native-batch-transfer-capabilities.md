# Source-specific typed batch transfer prerequisites

In **Program → Native backup defaults**, expand operation support, include combined
operations and typed batch compilation, then enable **Include source prerequisites
for typed batch transfer**. The existing table gains one source preflight row.
The controller batch panel also explains a selected Enum without a captured fixed
saved-value slot. Its separate local compilation remains available.

Explicit `native-backup-operation-capabilities/21` retains the complete profile20
report and adds only typed batch transfer prerequisite evidence. API default12,
ordinary UI14 and explicit profiles11–20 retain their contracts. No model name
supplies an inventory or implies another operation's support.

## Actual source and bounded compiler evidence

The existing retained Files3/11/12 reader and independent effective-default
compiler must agree on actual fields, file hashes, merge and identity. Recorded
Real/Boolean defaults are candidates. An Enum also requires the actual fixed
saved-value slot accepted by the existing transfer compiler. Every field retains
its source binding and prerequisite explanation.

One hypothetical request tests the first at most sixteen candidates in source
order through the actual typed batch transfer compiler. Deterministic zero/one
values differ from the captured value; Boolean values toggle. These values do
not establish useful sequences or Enum meanings. Evidence includes the exact
source, request, compiler report and hashes checked against actual output bytes.

A readable source with no eligible candidate retains its field evidence. An
unreadable source is unsupported. A failed bounded compilation is **not evaluated**
and retains its error and attempt count; it does not establish that every other
subset or value fails. Serial/BBMD/offline capture metadata neither prevents local
source analysis nor grants current transport readiness.

Analysis creates no draft, review token, retained plan or transfer receipt and
makes no controller query. Current-device identity, fresh selected values,
unselected-setting merge, explicit confirmations and complete field readback
remain the separate [batch transfer workflow](native-default-batch-transfer.md).

## Interface evidence and lifetime

The browser checks the entire previous profile, exact new schema, source-derived
candidate selection and compiler proof. Contradictory counts, prerequisites,
authority or compiler evidence are refused. Exact analysis downloads preserve
the received response bytes. Source/task/mode changes retire old results and
downloads synchronously, including coalesced away-and-back changes. Late replies
cannot replace newer evidence. Existing unfinished drafts, entry paths, teal
layout, keyboard table access and offline local copies retain their behavior.

This source preflight completes one scoped capability feature. General native
authoring, new blocks/I/O, previous-value batch recovery, packages/resources,
runtime/CCT comparison and physical/BTCVT acceptance remain separate. JCI-01,
JCI-03 and JCI-09 remain partial overall.
