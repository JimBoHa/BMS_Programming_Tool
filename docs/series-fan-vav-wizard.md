# Occupied series fan-powered VAV foundation

The series-fan API creates a separate editable ordinary graph for one single-speed series fan, calibrated **primary** airflow feedback, a primary damper and proportional hot-water reheat. It provides occupied operation and shutdown outside the raw request. A series fan sits in the common discharge path and may recirculate air when primary flow is low. This application is distinct from parallel fan reheat and from inline reheat without a fan. The user's earlier application named “series reheat” was clarified as inline reheat; that existing meaning is preserved.

This authored portable program is not a native JCI standard application, controller package, compiled CAF, hardware allocation, physical protection or Guideline 36/Title 24 acceptance. Cold primary air and separately calibrated primary-flow values are engineering prerequisites. No primary-flow calculation from velocity pressure or fan-volume commissioning is performed.

## Primary criteria and explicit departures

The reference is [JCI Controller Tool Help, edition 18.0, LIT-12011147](https://docs.johnsoncontrols.com/bas/r/Metasys/en-US/Controller-Tool-Help/18.0), original PDF SHA-256 `68935362c85cb1879dc033cc701115e8ea7c4ecb26748f21a9ceaf0454f82903`. PDF 585–587 distinguishes primary-damper, series/parallel fan and coil options. PDF 589 supports direct zone-temperature proportional reheat. PDF 590 distinguishes occupancy scheduling and shutdown from unoccupied operation. The profile supports the occupied/shutdown subset only.

PDF 1168–1169 names Series Fan Determination and describes occupied fan operation, unoccupied thresholds and purge, but its opening sentence calls the fan parallel. That conflict is retained in the profile. Its hidden native state implementation and reliability fallback are not reproduced. PDF 587's fixed balance setting and PDF 837–839's variable-speed G36 algorithm are separate source contexts, both outside this single-speed scope.

PDF 839–840 supplies 90-second estimated damper travel and 15-second stable fan-status defaults for a G36 startup module. Here those numbers initialize visible logical durations. They are estimates, not measured closure, and do not establish a G36 implementation. That source waits indefinitely for absent initial status and retains control after later status loss. This profile instead uses an authored bounded startup deadline and immediate latched stop after lost running proof. The source's damper-feedback/2% text is not turned into an invented native actuator-position estimator.

## Request, admission and state

Nine required logical inputs are generated: `occupied`, `unit_enable`, `energy_holdoff`, `fan_proven`, `fan_reset`, `zone_temperature`, `heating_setpoint`, `cooling_setpoint`, and `primary_airflow`. Their initial values are simulation defaults. The raw request is occupied AND unit-enable AND NOT energy-holdoff. It is evaluated separately from engineering-value admission and fault state.

Good-value admission requires ordered heating/cooling setpoints, zone/setpoint values within -50..100 °C equivalents, and primary airflow within 0..1,000,000 L/s equivalents. An invalid good-quality value immediately suppresses fan, damper and reheat, clears readiness and restarts startup timing. It does not itself create a proof-fault latch or count as operator off. These broad authored bounds are not calibrated physical operating limits. A simultaneous actual loss of previously running proof can still latch independently.

The declared positive whole-second scan and every timing value must align. Each successful scan represents one elapsed interval. The close TimerOn receives the admitted request while the prior fault is clear. During close, fan, damper and reheat remain off. Fan startup begins on the scan **after** the full close interval completes. With default one-second scans and a 90-second close estimate, requested scans 1–90 hold the fan off; scan 91 first requests it. Stable proof is counted only during fan request. With proof already true, the default 15-second proof completes on scan 105. Proof being true during close does not shorten that interval.

The separate startup deadline begins with fan request and continues across proof chatter. The default is 60 seconds, and it may equal the stable-proof duration. Stable proof completed at that exact deadline wins; a true deadline diagnostic alone does not imply a trip. Missing or chattering proof through the deadline latches a fault. After a ready scan, good-quality proof loss immediately latches and stops all three ordinary commands in that same scan. No automatic retry or running recovery interval is added.

The latch clears only when the **raw** request is off and `fan_reset` has a fresh rising edge. Holding reset while invalid values inhibit control cannot clear a latch. Later removing the raw request while reset remains high cannot create another edge. Once cleared, the next raw request repeats the complete close/start sequence. Permission loss outside a fault immediately stops commands and resets startup without inventing an electric-coil purge.

The 24-output manifest is derived from the actual generated graph. It includes request/value-admission indicators, close/proof/deadline indicators, readiness, fault/reset, fan command, thermal activity/demand, primary target/measured airflow, damper and reheat. `zone_range_valid` means good-value range admission; it is distinct from input quality. Authored `series_state` values are 0 off, 1 close, 2 fan-start, 3 run and 4 fault. `thermal_state` values are 0 neutral, 1 heating and 2 cooling. These are not native JCI enumeration values. Close/proof indications are logical timer results, not measured physical motion or airflow.

## Temperature, flow and hot-water control

Both heating and cooling setpoints are logical inputs with separately declared defaults. Effective targets from another ordinary graph, including the zone target composer, may be supplied as values; no native occupancy objects or automatic graph linking are inferred. The positive entry difference must exceed the nonnegative release difference. Heating/cooling modes are mutually exclusive. A mode enters at its declared temperature error, remains active until the opposite release boundary is reached and its previous selected demand is zero, or switches directly on the opposite entry condition. This command-aware release permits an active integral loop to retain a positive command at setpoint.

The reverse-action zone cooling P/PI output maps 0–100% to declared minimum/maximum primary airflow. A forward primary-flow P/PI compares that target with calibrated primary airflow and commands the primary damper. It runs whenever ready, including neutral/heating when the target is the primary minimum. Zone heating P/PI directly commands the hot-water valve. Inactive loops receive zero error and retain integral memory while their selected commands are zero. Disabling or changing modes does not reset their integrals or emulate native adaptive tuning.

Reheat uses logical run readiness and fan proof. **There is no invented primary-flow threshold for coil airflow.** Primary flow can be zero while a series fan recirculates. This profile has no measured total coil flow, physical heater interlock, discharge-temperature limit or safety circuit. Fan commands and status are logical values, not a physical protection guarantee. Only proportional hot-water heat is accepted; electric/staged heat, floating/two-position valves and supplemental heat remain separate work.

Absolute temperatures, differences and inverse-temperature gains convert together between degF/degC. Primary minimum/maximum/default airflow and inverse-flow gains convert together between cfm/L/s using the existing definition `1 cfm = 0.4719474432 L/s`. Identity, flags and timing remain unchanged. Canonical bounds apply to gains and values. The unchanged core uses binary64 and the current native IEC host uses REAL/float32; converted decimal values can round differently. Parameter conversion does not promise identical nonlinear trajectories, native tuning equivalence or native controller deployment.

## Bad quality, startup and local evidence

Every required input is evaluated by the existing transactional runtime. Bad quality or nonfinite arithmetic rolls back the entire scan, including timers, modes, integrals and commands, even when another input requests shutdown. A prior positive fan/damper/valve command can therefore remain committed after a failed scan. That is distinct from a successful scan with false permission, invalid good values or lost proof. Before the first successful scan, there is no preseeded safe command set: core output snapshots can be empty and the current native host initializes numeric/Boolean outputs to zero/false. Neither observation establishes physical shutdown.

Core/API checks cover real graph dependencies, default 90/15 timing, exact deadline ordering, early/chattering/missing proof, latched loss/reset, valid and invalid setpoints/flow, primary feedback, zero-primary hot-water operation, inactive integral hold, coupled units, original exports and saved revisions. Actual host IEC checks compile and execute ordinary generated ST through the pinned unchanged MatIEC/clang path across temperature/flow units, P/PI and scan variants. Original Program/ST/C/executable artifacts and decoded worker observations are retained privately; these are host execution results, not physical MS/TP/JCI controller results.

The first actual native attempt exposed a generated diagnostic name colliding with the existing compiler's automatic input-validity variable. The authored output was renamed to `zone_range_valid`; compiler/SDK behavior was not changed. The original compile refusals remain separate evidence. Failed constructors automatically removed their compiler temporary files; retained pre-fix ST is explicitly labelled deterministic reconstruction. A separate general symbol-namespace improvement remains future work, rather than imposing this output-name workaround on arbitrary programs.

## API and remaining scope

`GET /api/series-fan-vav-wizard/catalog` returns the hashed `studio-occupied-series-fan-vav/1` profile, fixed topology, exact Choices schema and valid off defaults. Token-protected `POST /preview` and `/export` accept `{ "choices": <Choices> }`. Preview supports the existing original Program-source response transport and returns source/profile/choice/Program hashes, actual point manifests, diagnostics and explicit false native-compile/controller-write flags. Export returns the original review JSON with `X-File-SHA256`. `POST /units` additionally requires both `temperature_unit` and `flow_unit`, and binds original and converted Choices separately. None of these endpoints opens a field interface, scans, creates a power lease or writes a controller.

`VAV-SERIES-001` is the bounded authored occupied single-speed, primary-feedback, hot-water foundation. Broad `MF-8a75247a85` remains partial. Native JCI allocation/compiler/CAF/transfer, physical commissioning, calibration/box balancing, variable/parallel fan algorithms, unoccupied recovery/purge/standby/bypass, warm primary air, adaptive tuning, discharge-temperature limits, supplemental/staged/electric heat, measured ventilation/CO2/exhaust coordination and complete G36/Title 24 acceptance remain incomplete.

## Web workflow

Open **Equipment wizard → Series-fan VAV wizard** to declare the project/target, temperature and primary-flow units, setpoint and loop parameters, startup durations and logical input defaults. Preview lists the actual graph interfaces and source-qualified behavior. Create replaces the editor with a separate editable portable project after the existing source guard/confirmation. Changes, discarded responses and leaving the wizard invalidate pending preview/create/export authority. Original review JSON downloads retain the server response Blob and verify its byte digest against the accepted preview; these hashes establish portable content consistency, not manufacturer authentication or independent native JCI compilation. Unit conversion errors preserve the original draft, including finite-precision cases where distinct source thresholds collapse to an invalid target pair.
