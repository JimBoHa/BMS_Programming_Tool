# Bounded idle-sleep requests during native transfer

App-managed Temco native program apply now owns an advisory idle-sleep request on the backend host. It starts after plan/session admission and connection-lock admission, before live identity/snapshot work. The same request remains owned through stop/write/readback/resume, durable outcome recording and any existing shielded recovery. It releases when that operation finishes, including cancellation cleanup.

No request is acquired merely because Studio, a browser tab, a BACnet connection, a saved plan or an idle native simulator is open. Inspect/plan/review waits do not hold one. Standalone `TemcoTransfer` SDK callers get no automatic request unless they explicitly pass an `OperationPower` manager. Other controller/capture services do not yet integrate this feature; native JCI compilation/download remains a separate incomplete path.

The profile is `studio-operation-idle-awake/1`. `GET /api/operation-power` returns its hash, backend provider/availability, admission state and bounded active/recent rows. Each row identifies an opaque lease, operation kind, lifetime, timestamps, request state, cleanup confirmation and an advisory error. There is no generic public acquire/renew endpoint. The first integration uses 900 seconds, with an overall 1800-second lifetime ceiling, at most eight concurrent requests and 32 completed history rows. Status polling cannot renew a request.

Availability means a provider can be attempted; an active request is not proof the computer cannot sleep. Failure, capacity exhaustion or expiry remains visible and does not authorize, cancel, retry or roll back controller work. Existing protocol packets, plan/backup hashes, receipt meanings and transfer deadlines remain unchanged. Expiry releases the power request only. An unexpectedly long operation may continue without protection; no endless automatic renewal is used.

On macOS, an owned `/usr/bin/caffeinate` child uses idle-system protection, a finite timeout and backend-PID lifetime. No utility is passed, because utility mode ignores the timeout. Display, user-active, disk and AC-only full-system flags are omitted. Only that child is terminated/waited/reaped; other processes’ assertions are untouched. A short local acceptance probe observed the exact owned PID’s idle request and its removal after explicit release and TTL. No power preference was changed.

On Windows, a dedicated daemon thread acquires `ES_CONTINUOUS | ES_SYSTEM_REQUIRED` and clears with `ES_CONTINUOUS` on that same thread. Display and away-mode flags are omitted. The daemon cannot keep the backend process alive for the lease lifetime during process shutdown. Ordinary same-thread calls, failure and cleanup behavior have software tests; real Windows acceptance is separately required. Linux/non-logind/other hosts currently report unavailable; an executable name or mocked provider is not represented as a verified Linux inhibitor.

Manager shutdown stops new admission and returns an explicit bounded pending-active observation. It does not stop an existing operation’s lease or cancel a transfer/recovery. The operation retains ownership until its `finally`, hard TTL or process death. This does not change Studio’s existing BACnet/application shutdown policy or establish uninterrupted recovery after host/process failure. Cleanup failure remains visible, rather than being mislabeled released; uncertain active resources continue to occupy capacity.

A provider request affects **this backend OS**. A Windows guest request does not keep its physical Mac host awake, and a local server request does not protect a remote computer. Explicit Sleep, lid closure, shutdown, battery exhaustion, power loss and OS policy are not prevented. Modern Standby/battery behavior is qualified. No hardware sleep-prevention, physical transfer or interruption-proof guarantee is established.

Primary OS references are the host’s `caffeinate(8)`/`pmset(1)` manuals and Microsoft’s [SetThreadExecutionState](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-setthreadexecutionstate) and [System Sleep Criteria](https://learn.microsoft.com/en-us/windows/win32/power/system-sleep-criteria). Future Linux support must qualify the exact [logind inhibitor](https://systemd.io/INHIBITOR_LOCKS/) lifecycle and request idle only, without blocking explicit user sleep/shutdown by default. JCI MAP Update Tool Guide 1.0.1, LIT-12012979 PDF 15, documents host sleep/power interruption for that particular updater; it does not supply a generic CCT/PCT/Temco automatic-resume contract.

Tests cover startup/plan absence, concurrent owners, TTL, cancellation during acquisition, same-thread Windows calls and failures, advisory unsupported providers, bounded history, shutdown admission and real local UDP transfer/recovery comparisons. Deliberate repeated cancellation retains the request and BACnet lock through original-image restoration. Earlier browser/Temco timeouts remain preserved and unexplained; this feature is not claimed as their verified fix. Bounded File/hardware/schedule/history captures, finite native test wrappers, Linux and coordinated VM-host protection remain future integrations.

## Read-only web status

The Connect tab includes **Operation power status**. The panel performs no status request on mount and does not poll. **Refresh operation power status** makes one read-only snapshot request; it does not acquire, renew or release a request. Rows preserve exact opaque lease IDs and UTC timestamp strings. Active classification follows the backend, including a cleanup-failed request that may still be active. Availability indicates that a provider may be attempted, not verified physical awake state. This view inventories only this manager’s requests, not unrelated OS assertions.

Each accepted snapshot retains its actual original HTTP response Blob with the displayed checked data. **Export original power status JSON** saves those bytes; its filename and displayed SHA-256 are computed locally from the body. The GET endpoint follows the existing read policy, and the UI uses the normal session-token helper. The local digest is not a server signature, manufacturer authentication, native JCI support or proof that a VM host or remote computer is protected.

A refresh retires the prior snapshot/export immediately. Failed, malformed or unsupported-profile replies leave no old export authority. Request generations, explicit discard and unmount retirement prevent a held older reply from replacing a newer observation or causing a download. The editor’s graph is unrelated to this backend-global status. No public lease-acquire, renewal, release or power-preference controls are added.
