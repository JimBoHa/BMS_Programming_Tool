# Selected-controller schedule deployment

Weekly-day deployment belongs to the controller open in the workspace. A saved
capture retains its original Device identifier, station address, router and
destination network. Opening a capture from another station remains useful for
local editing and export, but cannot grant field authority under the current
controller's header.

Schedule inventory passes its authoritative controller defaults through the
capture library to the deployment panel. Editable form state does not substitute
another target. Preview, Apply and read-only receipt reconciliation require an
exact selected-target match. Local receipt viewing and exact-byte export remain
available under another selection or offline.

The selected target participates in response ownership before effects run. Each
boundary change advances a revision, so returning A → B → A cannot restore an
earlier asynchronous request's authority. A reviewed Apply also checks the
prepared target against both the selected controller and source draft before
posting. Backend source checks, leases, one-use plans, native wire validation,
single-attempt dispatch and durable uncertainty/readback contracts remain
unchanged. This UI integration adds no protocol write service.

The existing workspace entry paths remain **Connect to a controller** and
**Open a CAF file** or **New application**. The latter paths retain local native
draft review/export without opening an interface. There is no new destination,
address prompt or inventory chosen by controller model.

Scope remains one existing supported weekly day and the separately qualified
UTF-8 String Schedule domain. Calendar deployment, exception/context engineering,
physical acceptance and broader manufacturer formats remain separate. Weekly
buffers still require export before leaving the task; source-specific unfinished
weekly-work retention is recorded as a remaining roadmap item. Calendar workspace
buffers keep their existing continuity behavior.
