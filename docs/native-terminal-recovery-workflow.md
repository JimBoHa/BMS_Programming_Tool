# Review a previous analog terminal in Points & I/O

`UI-NATIVE-TERMINAL-RECOVERY-001` adds **Previous input terminal** inside the
existing input configuration task. Select a retained native source and a matching
terminal-transfer receipt, then choose **Prepare previous input terminal**.
Only local evidence is read; neither a controller selection nor an open
interface is required. The controller, current CAF and retained source keep their
existing separate contexts.

Preparation independently validates the exact source/parent, typed current and
previous terminals, selected configuration, saved merge, compiler fingerprints,
inner compilation and complete numeric-token-preserving response seal. Malformed
or late evidence cannot stage a proposal or expose its download. The exact
original evidence JSON remains downloadable after successful admission.

## Stage and retain ordinary work

**Use previous input terminal** explicitly stages the inverse and saves the
ordinary input form separately in the existing bounded workspace draft. It
preserves unfinished text, such as `9.`, without parsing/reformatting it. Task
navigation retains both forms but retires reviews and confirmations. The staged
status shows the captured and previous terminals. **Return to saved input draft**
restores the original text and retires the inverse review.

Editing a staged proposal removes its recovery binding; the ordinary saved form
remains available. A fresh capture retires the old recovery origin and restores
the ordinary terminal text. Explicit discard clears both. This is in-memory
workspace retention, not durable storage across reloads. Changing candidates or
preparing evidence alone does not stage a different terminal edit.

## Local copy or field review

While disconnected, **Review local input copy** and **Save native copy** use the
existing saved-effective compiler/export without granting field authority. The
open CAF remains unchanged. Its native copy has a separately verified output
fingerprint and does not send an application.

For deployment, open the exact captured controller/interface and choose
**Review controller input change**. A staged recovery uses the separately
qualified [parent-bound review](native-terminal-recovery-transfer.md), retaining
its exact parent and sealed origin. Ordinary reviews reject injected recovery
metadata. The original complete terminal review seal/compiler and source checks
remain required. All three wiring, unchanged-mode/scaling and application-transfer
confirmations remain required before **Apply input change to controller**.

The client checks returned Apply/readback lineage against the exact reviewed
operation. Verified completion restores only its matching ordinary draft; an
unknown outcome keeps the staged work and original receipt for explicit readback.
An unrelated or older receipt cannot clear newer work. No old program is replayed
by reconciliation. Transfer can restart control, and capture/verification can
enter native backup state. Physical rewiring remains separate.

## Ownership and qualification

Source, receipt, draft, task and page lifecycle changes retire owned preparation
results, including delayed responses and digests. Existing review/Apply ownership,
32-workspace capacity, expiry, source selection and uncertainty rules remain.
The new controls reuse current styles/navigation; the engineering canvas and all
backend code remain unchanged.

Software qualification covers graph/CAF offline entry, exact local downloads,
unfinished ordinary text, navigation/return/fresh-capture behavior, malformed and
late preparation, direct/routed transfers, parent lineage, unknown readback without
replay and matching-only draft restoration. Tests use authored local controllers.
No live-site, VM or Bluetooth operation is included. General rollback,
binary/SA/cross-host movement, native resources/packages and physical/CCT acceptance
remain separate. JCI-10 and IO-02 remain partial overall.
