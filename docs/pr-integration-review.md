# Integrating PRs with the reviewed application

Use current main as the integration base, then compare proposed behavior with the
locally reviewed application. Locally tested workflows take priority when there
is a conflict. Preserve the useful improvement by adapting its implementation
instead of replacing an entire file from either side.

Protect the controller/file entry paths, named router and trunk selection, exact
controller route, connected configuration and native diagrams. Preserve local
drafts and original backups, source and identity checks, one-use reviews,
settings preservation, transfer budgets and uncertainty readback. New operations
belong inside the existing task groups. LAN hashing and secure operation IDs must
continue working on ordinary HTTP.

## Verification and installation

Run focused preservation, identity, parameter and affected compiler/API tests
against authored data. Exercise controller and CAF entry paths, named discovery,
diagrams, draft continuity, navigation/target retirement and downloads in the
browser. Test each changed field operation with owned protocol peers; an
interface change does not justify physical controller writes.

Keep the reviewed running source and private state backed up before deployment.
Require no active transfer, owned command or poller before replacing its backend.
Validate a private copy of the runtime state first, retain immutable evidence and
recovery records, and keep a rollback path. Reconnect only the engineering
interface after startup checks; do not replay controller writes or resume
pollers automatically. Keep the detailed machine-specific comparison and logs
outside Git. A source or software test does not establish new physical/CCT
acceptance for a recently integrated operation.
