# Native backup operation capabilities

In **Program → Native backup defaults**, select a retained backup, **Inspect
retained native backup**, then open **Operation support for this native backup**.
This local analysis reads the original, integrity-checked Files 3/11/12. It does
not open a connection, issue backup-state commands, create an edit or transfer
intent, or qualify the currently running controller. Original acquisition effects
and evidence remain unchanged.

The table separates thirteen operations. Archive and diagram reading use actual
recognized content. Typed instance/name copies require the stricter native
identity framing; name copies also require a typed Device name. Archive Real
copies require actual existing supported fields. Saved-setting merging requires
recognized selectors, values, checksums and complete coverage. Effective-default
compilation shares the exact source qualification with the installed compiler:
retained vendor/root identity, known saved layout, preserved identity and signal
membership, and actual supported class 526/527 Real fields.

A readable archive can therefore coexist with unavailable compilation. An unknown
saved layout does not hide readable records. A successful saved merge without
supported Real fields does not grant the default editor. Identity is recomputed
from actual bytes and compared with the retained acquisition; the manifest's
historical verification flag alone cannot qualify a source. Model names never
select replacement logic or inventories.

Offline qualification is independent of the current interface. Transfer rows
separately check the captured interface profile and can say **preflight required**,
**transport unavailable**, **source mismatch** or **unsupported source**. Even a
qualified direct or explicit routed IPv4 backup does not prepare a write. The
existing connected workflows still require the exact target and interface,
native credentials, a fresh backup, prior-value/settings/capacity checks, one-use
review and complete readback. Backup/readback can use backup-state commands.

General native logic generation remains unavailable. Release/package compatibility
is not evaluated; captured firmware and native ACS/DMCS values are separate
namespaces. Physical acceptance is not inferred. This feature does not correlate
transfer receipts or grant support for new protocols, formats, hardware allocation
or package migrations. JCI-01 remains partial overall.

The token-admitted `POST
/api/bacnet/controller/native-application/inspection/capabilities` accepts only
capture ID and manifest hash. All retained files and the manifest are verified
before analysis. It returns inspection provenance plus capability profile
`native-backup-operation-capabilities/2`, thirteen ordered rows and detailed local
qualification evidence. It returns `read_only: true`, `controller_queries: false`,
`can_apply: false` and `current_identity_verified: false`.

The browser binds results to capture, manifest, archive hash and original station,
checks the operation/flag contract and rejects altered replies. Source, target,
interface and navigation changes retire the parent inspection before paint; late
analysis results cannot return after A→B→A selection. Independent compiler drafts
remain intact. Evidence is progressively disclosed in existing Program tables.

Local checks use authored archives/saved bytes, strict HTTP admission, corrupted
files/seals, root/name/vendor mismatches, missing fields and direct/routed/serial/
foreign-device acquisition profiles. An actual UDP native backup is disconnected
before analysis, with zero additional peer requests and no transfer journal entry.
Chromium/WebKit checks cover offline statuses, drafts, altered responses and held
replies. These checks do not establish physical controller or Bluetooth acceptance.

Profile 2 adds a separate [Boolean default archive copy](native-boolean-default-copies.md)
row. Actual canonical class 530/531 Boolean fields qualify that local copy;
effective-default compilation and connected default transfer remain Real-only.
