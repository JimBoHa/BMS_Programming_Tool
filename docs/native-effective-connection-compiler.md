# Saved-effective native matching connection compilation

In **Program → Native backup defaults**, inspect a retained native activity or
control sequence. Choose **Add matching connection**, then **Native connection
basis → Saved effective snapshot**. **Open saved connection candidates** merges
the retained saved values before deriving eligible endpoints. Choose a recorded
prototype, observed matching output and unused matching input, then **Review
saved connection compilation**. **Save effective connection compilation** exports
a separate MOI file. The adjacent review action saves the original response JSON.
All these actions are local, including while a controller is selected.

This is `FMT-NATIVE-EFFECTIVE-CONNECTION-001`, with profile
`native-effective-connection-compiler/1`. The inner append keeps the separately
qualified `tagged-moi-connection-copy/1` contract. **Original archive** retains
its existing unmerged copy profile, labels, draft keys and export behavior.
An unsupported saved schema does not prevent qualified original-archive copying
or read-only inspection. Existing source substitution, transfer and recovery
remain separate operations.

## Saved values before the new connection

Source admission requires an identity-qualified vendor-5 snapshot whose Device,
name and model agree with the actual original native root. The immutable manifest
and Files 3/11/12 are checked on every source, review and export call. The existing
[saved parameter merge](native-parameter-storage.md) supplies typed, CRC-checked
values and its existing framing, duplicate-selector, datatype and size guards.
Non-application and unsaved runtime slots retain their existing handling; no
controller-model inventory or replacement program supplies missing values.

The existing [effective wire compiler](native-effective-wire-compiler.md) guards
native identity, references, object IDs, record membership, graph members, existing
wires, execution order and layout across the merge. This profile additionally
requires optional connection continuation property 3384 to remain byte-exact;
saved changes or insertion of that property refuse compilation. Candidates are
derived from the resulting captured effective configuration.

The [matching connection compiler](native-matching-connection-copies.md) then
appends one recorded-prototype edge between existing members. All its class,
configuration, observed-pin, unused-input, execution-order, cycle, continuation,
tag/size, record framing, index-width and exact independent native readback guards
remain. Other merged expanded bytes stay exact. The original archive, saved files
and retained manifest remain unchanged.

The review preserves original and effective source hashes, all three file
digests, the exact merge report, guarded request and nested connection proof.
The outer compilation has a separate deterministic seal. A historical saved
merge is not a fresh-setting guarantee or a current controller measurement.

## API, drafts and result ownership

The strict token-admitted API prefix is
`/api/bacnet/controller/native-application/inspection/effective-connection-copy`:

| Endpoint | Result |
| --- | --- |
| `POST /source` | Original provenance, saved-merge proof, effective diagram and matching candidates |
| `POST /preview` | Recomputed saved-effective compilation, exact request, nested append proof and review seal |
| `POST /export` | Recomputed reviewed artifact with artifact, review, snapshot, original source and outer compilation digest headers |

There is no Apply route. The request binds the original snapshot/File 3/diagram,
effective File 3/diagram, both connection properties, prototype tuple/index,
connection count and exact source/target references. Unknown fields, wrong types,
stale original/effective hashes and reused reviews are refused. Responses keep
current identity unverified, field transfer disabled and controller queries/writes
false.

Archive and effective proposals use separate keys in the existing bounded wire
draft cache. Basis selection is retained without evicting other work or raising
the 256-slot limit. Switching bases requires explicit candidate inspection and
retires reviews; navigation keeps proposals and never restores authority. Source,
route/interface, operation, basis, proposal, field-busy and lifecycle changes
retire pending results, including A→B→A transitions. Downloads check the actual
file digest and all five proof headers. Exact review downloads preserve original
response bytes rather than reserializing the evidence.

Software checks use independently authored retained Real/Boolean values, literal
new connection bytes, both graph classes, raw/gzip and short/extended frames,
continuation before/after connection data, exact unrelated byte preservation,
identity/schema/CRC/continuation/source/proposal refusals and immutable offline
HTTP. Browser checks exercise archive/effective separation, review/file proofs,
draft continuity, unsupported saved data, late responses, lifecycle, phone/keyboard
and authored routed context. Source and installed application/package checks are
separate; tests perform no site, VM or Bluetooth operation.

Saved-effective connection field transfer, arbitrary blocks or hardware allocation,
full resource/package/runtime compilation, native execution, CCT/PCT reopening
and physical/BTCVT acceptance remain separate. JCI-02, JCI-03 and JCI-09 stay
partial overall.
