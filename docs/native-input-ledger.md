# Native input receipts in Changes and History

Open **Workspace → Changes → Recorded changes** or **History → Recorded changes**.
Select the native record family to browse local input allocation, mode/scaling and
removal receipts alongside existing native operations. History exposes the same
read-only ledger; it adds no separate journal or feature destination.

Input rows identify the recorded operation, analog-input object, UI terminal and
requested allocation name when present. Details show the native reference,
requested and compiled values, exact Real32 rounding, signed zero, engineering
unit code and recorded wiring confirmation. These are recorded proposal/image
values. They do not establish current controller state, wiring or analog accuracy.

Removal details retain the recorded original allocation receipt ID. **Search
recorded allocation receipt** searches existing local records without loading or
revalidating a parent backup. Missing or archived parent material does not silently
become verified lineage. Original intent/result/events and the original source
JSON endpoint remain authoritative; downloading evidence preserves its exact
response bytes. A later readback does not rewrite the original uncertain dispatch.

The projection recognizes only `native-local-universal-input-transfer/1`. It
checks the strict recorded edit, compilation profile, object/terminal and edit
bindings, complete configuration fields, exact native Real32 values, unchanged
record/wire assertions and native payload hash binding. Removal additionally
checks the recorded allocation's action, object, terminal and native reference,
and rejects a self reference. Unknown profiles or inconsistent metadata retain
their original evidence with a clear unavailable state and no input tool link.

**Open input tools** opens Points & I/O while retaining the current controller and
file. It does not select the historical controller, import a proposal, transfer,
retry, reconcile or restore a token. Offline work opens the existing retained
native-copy workflow without connecting an interface. A connected workspace may
refresh its normal read-only inventory; field changes still require a separate
fresh review, confirmations, one-use Apply and readback.

Listing, searching, paging, viewing and exporting remain local. They do not call
protocol, backup, parent-validation or recovery services. Existing journal limits,
redaction, source seals, target/interface filtering, receipt outcomes and older
operation families remain unchanged. The browser validates the new metadata
shape independently before displaying configuration or exposing its tool link.

Checks use genuine receipts from authored UDP allocation, mode and removal
transactions, then reopen their store with an independent disconnected app.
They cover malformed/foreign bindings, original bytes, uncertainty and later
readback, explicit parent searches, graph/CAF entry, History, offline navigation,
response substitution and phone layout. No site or Bluetooth operation is needed
for this recorded-evidence feature.
