# Source-specific terminal operation support

`FMT-NATIVE-TERMINAL-CAPABILITIES-001` adds **Terminal copy and transfer support**
inside Program's retained native backup operation analysis. Open the disclosure
to explicitly analyze the selected capture. It reports three separate operations:
an original local terminal copy, a saved-effective local terminal copy and an
existing analog terminal transfer preflight. It reuses the existing source and
engineering tables, with no new navigation, canvas or styles.

The explicit `native-backup-operation-capabilities/15` API report wraps the full
profile-14 report and appends three rows. Default profile 12 and explicit profiles
11, 12, 13 and 14 retain their complete previous 22/24/25/27-row contracts. The
existing main table still requests 14; opening the terminal disclosure separately
requests 15 and shows its three terminal rows. Original exact JSON downloads stay
separate; the terminal download preserves the entire admitted profile-15 response.

## Actual source witnesses

Local analysis inspects actual input identities, recorded terminal labels and
typed Slot/Device Type properties. A candidate and a captured unassigned universal
destination must coexist. The existing compiler performs one discarded in-memory
copy to check its current source/encoding and returns source, record/property,
output and compilation fingerprints. It writes no output file, controller data,
review, token, intent or receipt. A model supplies only the already qualified
physical-capacity bounds; it does not supply a point list or a wiring claim.

The original local profile permits existing analog/binary universal input copies.
The saved-effective profile additionally requires the retained identity-qualified
File 3/11/12 merge and its original graph/continuation preservation checks.
Unknown saved structure or mismatched capture identity can leave original copying
available while withholding effective copying. Captured values remain separate
from current live values.

Analog transfer availability separately exercises native input transfer profile 2
with its captured configuration guard and preserved mode/scaling. It checks each
recorded local analog candidate until one qualifies. Explicit output-only terminal
namespaces can qualify this profile without widening either local copy profile.
Binary-only sources can qualify both local copy operations while withholding
analog field transfer. A matching retained vendor identity and captured plain
IPv4 are needed for `preflight-required`; serial/BBMD capture remains
`transport-unavailable` for this field profile. No field connection or plan is
created, and a current interface or controller is never inferred from the capture.

## Interface and verification

The browser checks exact capture/snapshot, all three original file sizes/hashes,
target, prior connection/removal evidence, native parent/object bindings, typed
slots, free-list order/uniqueness, compiler versions, configuration/merge hashes,
row status and explicit withheld authority. Contradictory evidence withholds only
the terminal table and download until an explicit reanalysis. Source/navigation
changes retire owned results, including late responses. The opened CAF remains
separate from the retained capture.

Software checks use authored sources including FX-PCV1630 and Metasys VMA1630,
binary/analog inputs, compression/framing variants, unknown saved/configuration
data, full captured terminals, output namespaces, host bindings, identity and
transport differences. Full older report projections and unchanged retained
files/receipt stores are checked. HTTP tests replace controller access and intent
creation with failing sentinels. Browser checks cover both entry paths, compact
and desktop layouts, exact downloads, independent admission and late results.

Captured free terminals require separate physical wiring and electrical checks.
Actual moves still use Points & I/O's local review/export or guarded field
Edit → Review → Apply → Verify workflow. General binary/SA/cross-host/dedicated
terminal movement, native resources/packages and CCT/physical/BTCVT acceptance
remain separate. IO-02, JCI-01 and JCI-09 remain partial overall.
