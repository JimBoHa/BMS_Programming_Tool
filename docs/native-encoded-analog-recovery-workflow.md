# Configured analog previous-terminal workflow

`UI-NATIVE-ENCODED-ANALOG-RECOVERY-001` adds recovery of a recorded previous
terminal inside Points & I/O → Move a configured analog input. It uses the
selected native capture and exact controller route in the existing graph or CAF
workspace. No new top-level destination, inventory or stylesheet is introduced.

Choose a matching recorded configured-analog transfer, then **Prepare previous
analog terminal**. Preparation reads retained local evidence. The browser checks
the complete sealed response, original response bytes, current capture, parent
receipt, typed configuration and field presence, terminal pair, original label
charset and literal changed payloads before offering **Stage previous analog
terminal**. An already-recorded binding provides evidence without an inverse edit.
Original preparation evidence remains downloadable without rewriting it.

Staging is explicit. It preserves the unfinished ordinary analog selection and
destination, along with the separate ordinary input form. **Restore ordinary
analog draft** recovers that selection. Editing the staged input or destination
retires its recovery lineage and requires a separate ordinary review. Switching
tasks retains bounded local drafts; changing source or target cannot transfer a
pending review to another controller. Delayed preparation, review and receipt
digests cannot restore retired authority after navigation or lifecycle changes.

An offline local copy uses the existing source-bound compiler and verifies the
exact downloaded image. Field work uses the separate parent-bound recovery review
route and requires a fresh review and all three confirmations. The browser binds
all recovery lineage fields across review, Apply and readback. The existing writer
revalidates original evidence, current source/settings/identity/route, preserves
other saved values and independently verifies native and published results.
Uncertain outcomes retain the receipt and use explicit readback without another
transfer. A verified result restores the ordinary draft and marks the old source
stale. A historical receipt never supplies new field authority.

Verification uses authored files and owned direct/routed localhost UDP peers.
Coverage includes graph/CAF entry at desktop/phone sizes, exact original evidence
and native image downloads, independent resealed-document/lineage refusal,
confirmations, uncertainty without replay, ordinary draft restoration and delayed
responses/digests across task/source/draft/lifecycle changes. Existing analog,
binary, ordinary input and legacy recovery workflows remain in focused regression
coverage. Packaging checks bind the wheel's modules/assets and UI provenance to
the committed candidate; installed Chromium and WebKit exercise that artifact.

Recorded recovery lineage in Changes/History remains next. General controller
restore/compilation, allocation/electrical changes, SA/cross-host movement,
packages/resources and physical/CCT/BTCVT acceptance remain separate. IO-02/JCI-10
remain partial. No live-site controller is modified by this qualification.
