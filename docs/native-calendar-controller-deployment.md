# Calendar controller deployment

Within **Schedules → Offline Calendar and Schedule library**, open a captured
Calendar, edit its dates and choose **Review Calendar dates**. Local review and
export remain available without a field connection. Expand **Open Calendar
deployment and receipts** for controller operations and retained evidence.

The open workspace controller must match the capture's Device, address, router
and network exactly. Enter a declared operator and rationale, then choose
**Review Calendar controller change**. This performs the backend's fresh identity,
static-context, protocol-revision and request-size checks. A qualified review
offers **Apply Calendar dates** for one complete Date_List replacement. A no-op,
stale source or unsupported target receives a reason instead of Apply authority.
The operator and rationale are user declarations, not authenticated site identity.
DateRange endpoints have a separate [field admission check](native-calendar-date-ranges.md).
The range editor explains fully specified dates and wholly unspecified endpoints;
local encoding/export alone does not qualify a range for controller deployment.

Apply consumes its local authority before the request begins. The existing
[`native-calendar-reviewed-date-list-write/1` backend](native-calendar-write.md)
retains its one-use plan, single unsegmented WriteProperty, durable journal,
ownership and cancellation rules. The interface does not add automatic retries,
reconnections or another transfer implementation. Review expiry stays retired
after a browser clock moves backward; the backend independently enforces its
monotonic deadline.

## Drafts, ownership and evidence

Changing dates, source, selected controller, interface, task or visibility retires
the field review. Returning to the original source or target cannot revive it.
Late replies cannot authorize Apply or replace another selection's evidence.
Cancellation names the owned operation. A dispatched change may already have
applied; cancelling does not reverse it. Existing source-specific Calendar buffers
retain exact unfinished text during navigation, including invalid partial values.
Export work before restarting or reloading the application.

The receipt separates dispatch admission, protocol response and fresh readback.
A lost reply remains **Unknown**, even if readback finds the requested value.
Error or Reject remains **Rejected**, even if a later independent observation
finds a match. A successful readback requires both the proposed dates and other
static context to match. Read the current Calendar into a new capture before
preparing another change.

**Refresh Calendar receipts** reads only the local journal. Open and save the
original receipt even while offline or while another controller is selected.
An interrupted durable intent is displayed as unknown; reopening it never
resends the replacement. **Read back Calendar dates** requires its exact original
controller and an open interface. It creates a separate read-only observation
with zero writes and preserves the original intent/result bytes. Save the
original review, receipt and observation independently when retaining evidence.

## Qualification and limits

Authored direct and routed UDP peers check literal native Date, DateRange and
WeekNDay values, actual protocol revision, one-write behavior and independent
readback. Chromium and WebKit scenarios cover successful transfers, lost replies,
Error/Reject, stale and substituted responses, foreign targets, expiry and clock
rewind, source A→B→A, visibility, task navigation, interrupted-intent recovery,
named cancellation, no-op proposals and exact original receipt exports. Compact
and desktop layouts retain the existing teal workspace and labelled controls.

Previous weekly/String authorities remain unchanged. Calendar's additional
range admission preserves existing local seals and historical receipt readback.
This profile edits one existing standard Calendar's whole Date_List on plain
IPv4, direct or through an explicit BACnet router. It does not create objects,
edit exceptions or schedule links, evaluate timezones, compile CAF applications
or establish physical manufacturer acceptance. BBMD, segmentation and
serial/BTCVT deployment remain outside this profile. SCH-01–SCH-03 remain partial.
