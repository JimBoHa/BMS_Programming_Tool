# Native target support

The editor's model selector records intended hardware. A target is executable only when its encoder, runtime semantics, packages and deployment service are supported and verified. Protocol point access alone does not establish application programming support.

| Target | Authoring and exchange | Independent execution evidence | Application deployment |
|---|---|---|---|
| BMS Studio graph | 27 blocks, macros, calendars, versioned JSON/ST/PLCopen/GraphML | Python scan engine, scenarios and shared-system simulation | Local sandbox changes, state retention and rollback; no physical output driver |
| Sedona | Real kit source/binary, SAX, SAB and SCode; supported foreign standard-kit conversion | Actual pinned compiler and experimental native Unix SVM, all 27 blocks | Real Sox structural changes on owned loopback VMs; physical platform ABI/kits unverified |
| Temco Control Basic | Numbered BASIC and real native bytecode, explicit point mappings; checked authoring annotations | Actual manufacturer compiler/decode interpreter, all 27 blocks and nine examples over 60 scans | Local memory-point host; physical download/configuration/online replacement not implemented |
| Niagara BOG | Real ZIP/XML, 17 primitive graph kinds, bounded foreign conversion, byte-exact opaque archive inspection | Independent public pybog encoding fixture; converted graphs run in Studio | Niagara station/Workbench import and native execution unverified; no deployment service |
| JCI FX-PCV / Metasys VMA | Observed native CAF containers, scalar patches, source rewires and prototype-checked new connections between existing blocks | Archive/XML preservation and relationship readback on seven authorized samples | New block identities, native compiler/packages, firmware acceptance and application loader missing |
| ALC EIKON / WebCTRL | Public manuals and vendor-dependent Integration Builder workflow reviewed | No independent equipment compiler/runtime verified | Requires a supported licensed toolchain or an independently verified adapter |
| Honeywell Spyder / CIPer | Public programming manuals and native dependencies reviewed; generic BOG inspection can preserve unknown types | No proprietary component semantics/compiler verified | Native application compiler/modules and loader missing |
| External IEC PLC | ST and schema-valid PLCopen TC6 XML with an ST body | Local XSD verification; external IEC execution unverified | Requires a matching destination compiler, I/O mapping and deployment adapter |

Native Temco and Sedona execution does not make their bytecode executable on JCI, ALC or Honeywell firmware. Niagara event/status/priority behavior differs from Studio scan semantics. All native conversions expose their supported profile and reject unknown executable logic or configuration.

BACnet/IP, explicit routed destinations and direct legacy MS/TP provide addressed point discovery/reads and owned priority commands. Modbus TCP/RTU provides reads. Field sampling shares those BACnet interfaces explicitly. These services do not add controller application objects or create a sensor terminal. BTCVT's Bluetooth host protocol remains unimplemented.

Six native 2025 Title 24 CAF applications have not been delivered. The nine VAV example graphs are illustrative, even where their generated Temco/Sedona programs match the reference simulator. Controller eligibility, complete sequences, field commissioning and compliance evidence still require separate verification.

E2/F2 site access and the final GitHub push remain deferred under the user's instruction to finish programming first. Site credentials have not been read, and the site has not been contacted.
