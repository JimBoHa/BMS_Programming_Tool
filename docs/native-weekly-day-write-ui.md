# Reviewed native weekly-day deployment in Connect

The **Native weekly-day deployment** workspace connects the [offline capture/draft library](native-schedule-drafts.md) to the [guarded native write API](native-weekly-day-write.md). This is one existing standard BACnet Schedule day over direct unicast IPv4 or an explicit pinned router/DNET:MAC. It does not upload a CAF program, create a Schedule, change default/priority/targets, edit Calendar or exception data, or establish physical manufacturer/firmware acceptance.

1. Open a retained capture and review a typed weekly-day draft in Connect. The capture and reviewed draft identify the fixed Device, endpoint, router, Schedule and day. An offline draft supplies source evidence; it is never field-write authorization.
2. Open **Native deployment and local history**, enter a visible operator declaration and rationale, and select **Preview fresh native weekly-day write**. This explicitly reads current controller identities and context through the already-open supported interface. User declarations are text rather than authenticated site identity. Opening the workspace or local journal sends no controller queries.
3. Inspect the exact target/day, requested versus wire values, native context, unsegmented size/remote limit and remaining read/write race. Unsupported, changed or no-change previews do not offer Apply. A valid review has a short server lease. The GUI latches a received review as expired and disables Apply when its displayed expiry passes; reversing the browser clock cannot revive it. The server independently validates its authoritative lease and source/interface guards.
4. **Apply one native weekly-day request** consumes the GUI authority before waiting. The backend rechecks current configuration and commits durable intent before one unsegmented request. There is no automatic retry, reconnect, inverse write or rollback. Editing the reviewed source, connection selection or declarations, closing the workspace, or leaving Connect retires its GUI authority and requests cancellation of any still-active owned operation. Cancellation cannot undo an admitted write. A completed server preview token expires separately; cancellation does not claim to revoke an already-ready server plan.
5. Inspect independent receipt facts: whether a remote change may have happened, whether dispatch was admitted, native protocol response and fresh readback. A negative native response does not prove unchanged configuration. A matching readback does not prove authorship, output behavior or future persistence. Native ErrorClass/ErrorCode/Reject/Abort values retain their known labels or explicit unknown numeric codes.

The local journal remains available disconnected. Open a receipt to inspect its source-qualified outcome and export its original server bytes. An interrupted durable intent takes precedence over the old pre-send snapshot: dispatch, protocol acceptance and readback are **unknown**, and it **may have applied**. The original snapshot and its byte hash remain evidence, not a claim that transmission never happened. A lost or mismatched Apply reply directs the operator to this journal rather than enabling the old token again.

**Read-only reconcile selected receipt** explicitly reads that receipt's captured target and saves a separate downloadable observation in workspace memory. It sends zero writes and does not edit the original receipt or convert an uncertain historical result into an ACK. Export this observation before leaving. The backend still requires a matching supported open interface; other transports remain refused.

Preview, receipt and reconciliation downloads use the paired original HTTP Blob. Browser JSON previews can normalize `-0.0` or integral-float spelling, and are not used to reseal or reconstruct native evidence. Source/connection epochs, exact operation/source/day identities, current rule hashes and bounded response checks reject stale or mixed responses. Native values and discovered devices are not embedded in the application.

## Verification and limits

`web/tests/native-schedule-write.spec.ts` uses independently authored real UDP direct/routed peers and a worker-owned application/state directory. It checks exact one-send/native day tags, signed-zero receipt bytes and independent Python seals, protocol/readback disagreement, original-byte offline journal reopen, explicit read-only reconciliation, held-response/source/navigation guards, cancellation, malformed replies and clock-controlled expiry. The recovery fixture removes only the completion of its own actual recorded intent to exercise the unknown recovery view; it does not synthesize successful native evidence or mutate shared history.

The owned test server uses the installed package and compiled UI when `BMS_TEST_INSTALLED_TARGET` is supplied, verifies their paths and UI hashes, and runs outside the checkout. These loopback tests do not exercise a physical MS/TP trunk, BTCVT, real field controllers, proprietary CAF compilation or firmware execution. Broader native schedule engineering remains partial.
