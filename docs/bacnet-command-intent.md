# Exact operator intent in BACnet command previews

The Connections command field now parses numeric tokens before JavaScript can round them. Integer tokens must be exactly representable in binary64: `9007199254740993` and its negative are refused visibly before a preview request, while `9007199254740992` and `1152921504606846976` remain valid. Finite decimal and exponent tokens retain the existing binary64 execution profile; this does not promise arbitrary decimal precision. Numeric overflow, malformed numeric/JSON forms, null and containers cannot fall back to strings.

Bare enum labels such as `active` and `inactive`, JSON strings, and JSON `true`/`false` retain their scalar meanings. Numeric-looking labels need JSON quotes. Strings stay strings even when their contents look numeric or Boolean. The existing backend still decides whether that scalar is valid for the actual BinaryPV, Real, Double or Unsigned present-value datatype and the object's state count.

The command path reuses the shared source-token parser and exact request serializer. After execution-profile validation, numeric tokens remain source atoms in this one request body. This preserves the original integer token, explicit float spelling such as `1.0`, and floating negative zero `-0.0`; no new generic request behavior or server route is introduced. An integer `-0` has Python integer-zero semantics. Preserving `1.0` also lets the backend correctly reject a float for an integer-only multistate command.

A preview pairs its parsed receipt and original HTTP response text atomically. The original document must match the admitted target/object/priority/token and requested scalar. Integer comparisons use original tokens and `BigInt`; float comparisons use the finite binary64 profile and preserve the sign of floating zero. An adjacent incorrect integer cannot pass merely because its JavaScript Number projection matches. Source/interface changes or navigation retire pending publication, and editing the command clears both receipt and text.

The UI displays the server's original response text. `requested_value` is the admitted scalar, and `value` is the value after the native BACnet datatype's wire conversion. For example, requested integer `9007199254740994` is exact in binary64 but becomes `9007199254740992.0` for Real32. Preview does not acknowledge a controller write; Apply and Relinquish remain separate explicit operations with the existing server-side ownership and priority checks. There is no automatic apply, retry or field-write validation claim.

Verification uses an authored loopback-only BACnet peer that counts actual read and write services. Browser tests check refusal with zero preview HTTP requests and zero write frames, raw request and original response bytes, independent Python integer/type/IEEE32/sign checks, enum/Boolean apply and relinquish on that test peer, wrong-target/adjacent-integer receipts and delayed navigation. Existing pending-preview and direct-MS/TP UI fixtures remain regression checks. No building device, Bluetooth interface or credentials are used.
