# Local CAF Boolean constant creation

`FMT-CAF-BOOLEAN-COPY-001` copies one recorded version 1.0 Boolean Constant and
its required output child into a local CAF. The parent uses class/type 552,
properties 75/3184/32527/3670, exposed property 85 and recorded enum-set-432
standard-name code 13. Its class-531 output uses BACoid type 5 and exactly
properties 75/32527/3113/3365. The existing native Boolean text is retained;
numeric/string coercion, unknown schemas and omitted Boolean values are refused.
The profile copies configuration without assigning an undocumented meaning to
standard-name code 13 or promising controller execution.

The shared writer has explicit frozen Float and Boolean profile specifications.
The original Float schema, source/report fields, seals, route and output bytes
remain unchanged. Both profiles retain the existing global identity/reference
scan, two-ID allocation ceiling, exact hierarchical references, single-member
membership/order/layout additions, unrelated XML/ZIP preservation and independent
readback. The child identity is generated using its recorded type, rather than
assuming a Float output. Unknown bookkeeping and all prior resource bounds still
fail closed. No controller allocator or physical I/O is created.

Strict Boolean routes are separate from Float routes:
`/api/caf/{id}/boolean-constant-copy/source`, `/preview` and `/export`. They retain
session-token admission, exact source/selection/position/review binding, nested
creation proof and four artifact/review/source/creation headers. A Boolean review
does not qualify a Float operation or a changed proposal. There is no Apply route,
field plan, native File-3 compiler or controller query/write in this operation.

## Program workflow and local drafts

Open a CAF, select **Program → CAF file → Logic**, then inspect **Copy a recorded
Boolean Constant**. When the actual diagram contains both supported constant
types, **Constant type** selects the focused task. Only one editor and primary
action is visible. It does not populate controller inventories or templates from
a model name. Controller entry uses the existing **Local CAF file** tool and
retains the selected route while labelling the file/controller match unverified.

Float and Boolean drafts share the existing 32-context cache, keyed by actual
archive/diagram/prototype reference. Passive type selection consumes no slot;
unfinished coordinates survive type, prototype, module, task and file navigation.
The cache refuses new work at capacity without removing an older draft. Hidden
type editors retire their reviews and late exports while retaining local text.
Source/controller/lifecycle retirement, exact review JSON, checked artifact
downloads and clicked-draft save ownership retain their existing contracts.
The ordinary CAF Save, graph wiring and view-layout behavior remain separate.

Client reference lengths now count Unicode codepoints like the existing Python
512-character admission rule. Authored non-BMP Float and Boolean sources pass
the original source/selection/review seals and strict request models. The backend
limit is unchanged; UTF-16 storage units no longer reject a valid source early.

## Evidence and remaining scope

All four actual Boolean constant/output pairs in the seven authorized private CAF
originals were created and read back in memory. Every original stayed unchanged;
no derived private CAF was saved or committed. All 121 Float pairs were also run
through both the exact PR226 implementation and the shared writer. Their complete
source selections, creation reports, seals and output bytes match exactly.

Authored tests independently construct expected Boolean XML, paired identities,
graph arrays/order/layout and preserved values/metadata. They cover repeated
creation, native Boolean spellings, unknown/wrong types/schemas/codes/values,
mixed-profile isolation, strict local HTTP proof and subsequent existing guarded
connection creation. Source/installed browser tests exercise both entry paths,
type ABA, unfinished drafts, late output, Unicode proof, compact controls and
the unchanged Float/CAF editing and simulation regressions. Exact delivery counts
and package/preservation results are retained in the local qualification report.

This profile does not complete general authoring, vendor allocation/reserved IDs,
memory/scan resources, arbitrary block/port/hardware creation, native compilation,
CCT reopening, firmware/physical transfer or BTCVT. General compiler/download/new
object capability flags stay unqualified. JCI-02, JCI-03, JCI-06 and JCI-09 remain
partial. See [the original Float scope](caf-recorded-constant-creation.md).
