# Source-specific typed default batch support

In **Program → Native backup defaults**, inspect a retained native backup and
expand **Operation support for this native backup**. Enable **Include combined
default/connection and terminal operation support**, then **Include typed default
batch compilation support**. The existing engineering table gains one local
compiler row. Ordinary analysis and earlier explicit profiles keep their original
contracts.

The new `native-backup-operation-capabilities/20` profile retains the entire
profile 19 report before adding typed batch evidence. The API default remains
profile 12; the ordinary interface requests profile 14. Selecting this extension
does not change those defaults or imply support for another operation.

## Actual retained-source evidence

Analysis opens actual Files 3/11/12 through the existing batch reader. Its
independent compiler must agree on all original file hashes, the saved merge and
the complete field list. Actual recorded fields determine available types; a
model name supplies no invented inventory.

One hypothetical batch changes the first one to sixteen fields. A Real changes
to a different zero/one float32 value, a Boolean toggles, and an Enum changes to
a different representable zero/one numeric code within captured capacity. These
are compilation witnesses, not suggested sequences or verified Enum meanings.
Boolean-only and Enum-only sources require neither a Real field nor a connection
diagram.

The existing batch compiler checks each independent constituent edit, literal
unselected-byte preservation, record framing and both complete composition
orders. The witness also checks reported hashes against the actual compiled
container and expanded native image. Details retain the exact source, request
and compiler reports. Analysis calls neither the batch preview/export service nor controller
review, creates no retained proposal or plan, writes no journal and queries no
field interface. It remains useful after disconnection.

An unsupported source is separate from a failed bounded probe. Analysis tries
one batch of at most sixteen fields. If it fails, the row says **not evaluated**;
another subset or value may qualify. The report retains actual field/selection
counts, attempt count and error. A captured serial, BBMD or absent interface does
not demote a qualified local copy.

## Presentation and ownership

The browser independently validates the complete previous profile, batch source,
exact hypothetical request, constituent reports and composition chains.
Malformed, additional or contradictory authority is refused. **Save exact
operation analysis** saves the original received JSON bytes rather than a
reconstructed report.

Mode counters retire old displays and download actions synchronously, including
changes away and back before repaint. Retired responses cannot replace a newer
analysis. Source or task changes retain ordinary unfinished value drafts while
retiring the old analysis context. CAF and new-application entry paths preserve
the existing teal layout, focused tables and keyboard access.

This profile reports the separate [local batch compiler](native-default-batch.md).
It grants no batch field Apply, general native authoring, package/resource/runtime
validation, CCT equivalence or physical/Bluetooth acceptance. Earlier transfer
rows keep their independent preflight and readback requirements. JCI-01, JCI-03
and JCI-09 remain partial overall.


A separate opt-in [source prerequisite analysis](native-batch-transfer-capabilities.md)
adds profile21 evidence without changing this workflow's original contract or
creating controller authority.
