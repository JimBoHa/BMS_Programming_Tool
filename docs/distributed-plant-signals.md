# Source-bound distributed plant signal planning

System simulation → **Plant I/O and network engineering schedule** opens an offline workspace. Retain exact current-editor, saved-revision or uploaded portable Program JSON sources. Declare hosts, bind subsystem instances to immutable source hashes, assign each top-level Input/Output a role, and explicitly connect network outputs to inputs. Roles are sensor, command, network source, network destination or unassigned. Chiller, PCHWP, CWP, tower and SCHWP tags organize the declarations; they do not generate sequences.

The review detects missing hosts/roles/endpoints, duplicate role declarations, direction/type mismatches, multiple network writers, unlinked destinations and exact declared host/terminal collisions. Network fanout is allowed and reported. Numeric links require nonblank, exactly identical original unit text; whitespace-only units remain unknown. No unit conversion, label matching, SRC/DEST suffix matching, terminal aliases or implicit dimensionless units are inferred. Different source scan periods are retained without asserting synchronized execution.

Every table row carries source Program ID/name/revision, raw source and canonical hashes, instance/host/subsystem declarations, and interface identity/type/unit. Original terminal hints are separate source text. A declared model or terminal key does not establish an actual device, capacity, spare input, native allocation or physical connection. Every result carries `hardware_verified=false` and `native_mapping_verified=false`. “Software-consistent” means only that these declared interfaces and links pass the documented checks.

## Exact evidence and local captures

A source ID is SHA256 of its original UTF-8 JSON bytes. The source also retains the existing Program canonical digest, original revision text and original source text, including opaque numeric values; this feature does not execute the source. Sources with identical names or later revisions never replace existing bindings. Duplicate JSON keys, nonfinite numbers, HTTP source envelopes, duplicate node IDs and ambiguous Boolean structural numbers are refused. Internal blocks remain archival source; the reviewed interface is top-level Input/Output only, without macro expansion or native CAF interpretation.

Reviews contain the exact plan, complete original sources, regenerated I/O/network analysis, profile/rule/manual hashes, local review time and content seal. JSON export uses retained server bytes. CSV carries readable Program/revision/host/instance/subsystem labels, source hashes, fanout, review/profile/plan hashes and explicit unverified flags. Spreadsheet formula-leading text is escaped in CSV; original JSON/source text stays unchanged.

Save a review as a durable local capture, or import a sealed review. Capture ID is the SHA256 of the original review file bytes. Import verifies strict shape, profile, original source hashes, plan seal and independently regenerated analysis. It stores the capture without changing the session source catalog. **Open** explicitly adopts its original plan and source identities, without querying a controller. The original review bytes remain available after restart. Separate sealed metadata records local ingest time and local-review/import origin; duplicate identical imports preserve the original stored record. Self seals detect alteration; they do not authenticate an author, device, historical observation or manufacturer approval.

Review exports require the exact review ID and content seal. Changes to current Program, plan or source selection retire previous review authority and pending downloads; dirty plan replacement requires confirmation. Unexported declarations stay in workspace memory. Save/export before leaving or restarting. Explicit source/capture deletion changes only the selected local record.

## Bounds and failure behavior

Each source is at most1MiB; the session retains at most32 sources,8MiB original source bytes and16MiB serialized source records. A plan permits16 hosts,16 instances,4000 total instantiated nodes,1024 interfaces,1024 explicit assignments and1024 links. Diagnostics are bounded to4096; exceeding a bound fails the operation rather than silently truncating evidence. Individual reports are at most8MiB. The newest8 reviews share a32MiB session limit; an expired review requires a fresh review or reopening its capture.

Durable captures are limited to32 and64MiB of stored document plus metadata bytes, with no automatic eviction or overwrite. Save/import refuses store pressure or corruption. SQLite publication is transactional; duplicate capture identity preserves existing bytes and ingest metadata. Reopen restores all required source records or refuses without a partial catalog update. Stored blobs, seals and regenerated analysis are checked before use; malformed storage does not become an empty library. SQLite lock waits are bounded to250ms without automatic retries. Existing Store/file-system support applies; this feature does not add a power-loss durability guarantee.

## API and applicability

`GET /api/plant-signals/profile` returns only local profile/catalog/capture metadata. Token-protected source import/export/remove, review/export, and capture save/import/open/export/remove routes perform no field query or write. JSON parsing and multipart uploads have explicit byte limits; original server download bodies include `X-File-SHA256`.

Primary reference: JCI **Chilled Water Plant for Guideline36 Application Note**, LIT-12014531,1.0, PDF15–16,19–21 and49–54. Original PDF SHA256: `87298adc723f40cc5c0ff08d08822dbd7c931698e576b7c51b099f5a59c839d7`. [Official document](https://docs.johnsoncontrols.com/bas/r/Metasys/en-US/Chilled-Water-Plant-for-Guideline-36-Application-Note/1.0).

The manual describes five combinable subsystem applications, shared network signals that require explicit supervisory mapping, and distributed sensor/control points. This feature implements an engineering review criterion drawn from those descriptions. It does not copy the native plant applications or silently repair inconsistent signal names in the tables. No native hardware allocation, supervisory mapping deployment, authentication/display provisioning, controller connection, field read/write, plant simulation, native CAF compilation/transfer, complete G36/Title24 sequence or physical JCI acceptance is provided. Broad requirement MF-3aba872151 remains partial; COMM-PLANT-001 identifies this offline foundation.

Backend/API tests independently exercise conflict matrices, fanout, exact units, source/revision identity, raw numeric archival retention, strict JSON/typed proofs, resealed tampering, quotas, storage corruption/contention, restart and exact exports with networking forbidden. Browser tests author explicit plans, verify Python-regenerated downloaded seals and original bytes, reopen/import captures and reject stale/malformed responses in Chromium and WebKit. These are software checks, not commissioning evidence.
