# Saved-effective native execution-order compilation

In **Program → Native backup defaults**, select a retained backup and inspect its
captured native records. Inspect an actual activity/sequence, choose **Native
diagram operation → Change execution order**, then **Compile native execution
order → Inspect effective execution order**. Select an existing block and move
it earlier or later. **Review native execution-order compilation** rechecks the
original files and proposal. Save the separate MOI copy or its exact JSON review.

This implements `FMT-NATIVE-EFFECTIVE-ORDER-001`, profile
`native-effective-execution-order-compiler/1`, with the inner
`tagged-moi-execution-order-copy/1` profile. It extends native application
authoring under JCI-02/JCI-03. It creates no controller review or transfer plan.
The separate [CAF execution-order workflow](caf-execution-order.md), ordinary
native source substitution, connection addition/removal and field writers retain
their own contracts.

## Compiler and preservation

Admission uses one immutable, identity-qualified vendor-5 File 3/11/12 capture.
The original native root must match the recorded Device, name and model; a model
name never selects a replacement graph. The existing saved merge preserves its
CRC, slot/type, identity, object, graph membership, connection, order and layout
checks. This profile also requires continuation metadata to stay exact across
that merge. The resulting saved values are historical, not live measurements.

The selected class 536/575 diagram contains 1–512 actual existing members and at
most4,096 connections under the native reader's existing limits. Its recorded
execution order must be a complete permutation. Typed member Object_Identifier
values and original native object headers agree. The compiler walks the actual
Unsigned order tags, retains their one-to-four-byte payload widths and requires
their exact closing property boundary.

Every original wire preserves its source/destination execution relationship:
before, same block, or after. Existing backward/feedback/self connections are not
reinterpreted as an acyclic graph. New proposals must be complete permutations;
an index must fit the original width at its proposed position. An unavailable
move is explained without widening a native record or guessing a new encoding.

Only changed index payloads are replaced. Every other merged expanded byte,
including tag/record framing, identities, graph membership, links, metadata,
layout and unselected saved settings, remains exact. Gzip sources retain their
original ordinary header and get a recomputed compressed body/CRC/size. A no-op
returns the exact merged source, which can differ from the original archive when
saved values have advanced. Separate compressed and expanded hashes stay explicit.
Independent native/parser readback checks the entire expected image and diagram,
record membership and unchanged other records before export.

These are structural native-copy checks. They do not establish side effects
between independent blocks, complete runtime semantics, destination resource or
package compatibility, CCT/PCT acceptance or physical controller acceptance.

## API, proof and lifecycle

Strict token-protected local endpoints under
`/api/bacnet/controller/native-application/inspection/execution-order`:

| Route | Behavior |
| --- | --- |
| `POST /source` | Reload originals, merge saved settings, inspect actual order tags/members/wire phases and seal the source report |
| `POST /preview` | Recompute that source, require exact original/effective/selection hashes and compile the selected permutation |
| `POST /export` | Recompute the reviewed copy and return artifact, review, original source, snapshot and compilation hash headers |

The browser checks the selected capture, full recorded route, original files and
diagram hash, member/slot/order/phase consistency, complete source and nested
compilation/review seals, exact proposal, patch list and all five download headers.
It hashes the actual artifact before saving. Original response bytes remain
available for exact JSON export. Digests bind local evidence; they are not
manufacturer signatures or current controller verification.

Discrete proposals use the existing 256-slot native graph draft cache, with
separate source/record/operation keys. Inspection consumes no proposal slot.
Capacity refuses new work without eviction; returning to the original order or
explicit discard frees only that proposal. Unknown/mismatched retained text is
preserved for explicit discard. Navigation retains drafts while retiring reviews.
Source, operation, controller/interface, task, disclosure, visibility and page
changes retire pending results and cached callbacks. Synchronous operation and
render generations also handle coalesced away-and-back changes. Active field
operations keep their existing ownership rules. No native authority is restored.

## Qualification and remaining work

Authored byte oracles cover raw/gzip, short/extended records, both graph classes,
all four-member permutations, one-to-four-byte widths and 512-member boundaries,
backward/self connections, saved Real/Boolean preservation, exact merged no-op,
CRC/identity/schema/source refusals and strict offline HTTP. Browser checks cover
both entry paths, desktop/phone, keyboard, navigation, coalesced/late replies,
altered proofs/artifacts and authored routed-controller context.

Fresh controller review, guarded native order transfer/readback and recovery are
the next independent operation. General native authoring, new identities/links,
resource/package/runtime qualification, CCT comparison and physical/BTCVT
acceptance remain separate. JCI-02/JCI-03/JCI-09 stay partial overall.
