# Compare a retained source with a recorded batch result

Open the current retained backup in **Program → Native backup defaults**, expand
the typed batch/controller workflow and load a verified batch receipt. Choose
**Compare retained source with recorded result**. The comparison is local and
works without an open field interface. **Save exact result comparison** preserves
the original JSON response. Ordinary unfinished edit text remains separate.

Profile `native-default-batch-result-match/1` reconstructs the complete original
typed compilation and payload from the receipt's own immutable backup. The original
operation must have possible dispatch, a resolved outcome and an immutable verified
result or verified readback. A later inconclusive observation does not erase that
historical proof. Unknown, inconsistent, unverified or unresolved originals refuse
comparison. Supported recovery-child receipts use their own backup and result;
their earlier parents are not reopened or revalidated after dispatch.

## Separate comparisons

The report distinguishes the captured route and identity, expanded native
application, effective application after saved-setting merge, selected typed
defaults and saved directory from before the original transfer. Application and
effective-value matches use expanded native hashes. Container hashes remain
separate: a different valid gzip header does not change the native program.

Each originally selected field shows its recorded expected value and the current
retained effective value. Finite Real bits preserve signed zero; Boolean values
remain strict. Expected Enum codes retain the original transfer bounds. Observed
current Enum values may use their actual Unsigned32 range for read-only comparison;
this grants no wider compiler or transfer support. Missing or differently typed
current fields cannot count as matching. Enum storage/state metadata is compared
separately, with meanings and allowed-state membership still unverified.

Changed selected values are reported as differences, without requiring them to be
previous or recorded-after values. Unselected saved-setting changes can leave the
native program and every selected default matching while the complete effective
image differs. A different captured route remains different even when Device
instance, application and values agree. These observations never retarget the
workspace or turn a local source into current-device verification.

**Retained application and effective values match** requires source identity,
route, captured identity, both expanded application comparisons and every selected
value to match. The original saved-directory comparison remains separate: it is
evidence about the before-transfer directory, not proof of current compile/storage
eligibility. A match does not establish package, resource, runtime, CCT or physical
acceptance and cannot authorize a new transfer.

## Browser and API

The browser independently checks the receipt/proof, exact source and request
bindings, typed current/expected rows, comparison relationships and all no-authority
flags. Late or malformed responses cannot publish a comparison or download after
their source, receipt, task or visibility context retires. Exact JSON export keeps
the received bytes. Existing field review, credentials, confirmations, one-use
tokens, journals, limits and uncertainty recovery remain unchanged.

`POST /api/bacnet/controller/native-application/default-batch/result/compare`
requires the local session token and exactly `receipt_id`, `capture_id` and
`snapshot_sha256`. It reads retained evidence and performs bounded local
reconstruction. It creates no proposal, field plan, token, journal entry, controller
query, backup-state command, restore or reconciliation. New field work uses its
independent review/apply/verify workflow.

Qualification uses authored direct/routed captures and isolated source/installed
Chromium/WebKit workflows. No site, Bluetooth or physical-controller testing is
claimed. This completes one scoped retained-result comparison under JCI-01/JCI-10;
general authoring, conversion, wider recovery and native/physical acceptance remain
separate.
