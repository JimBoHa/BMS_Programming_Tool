# Recorded native point-name changes

**Changes** and **History → Recorded changes** now recognize
`native-point-name-transfer/1` receipts. Search can match the recorded object,
native reference and before/after names. Details show the original name, requested
name, character encoding, recorded confirmation and binding hashes. Names use JSON
string notation so empty originals and control characters remain distinguishable.

This is a projection of recorded intent and compilation data. It does not reopen
original backups, query a controller, obtain its current published name or grant
transfer authority. Original receipt JSON and its HTTP response bytes remain
available through the existing evidence download. Recorded outcome, dispatch,
uncertainty and readback keep their existing independent meanings; the proposed
name is not presented as a fresh live value.

The reader requires the exact known operation/compilation profiles, canonical
point selection, matching edit/reference/name/hash bindings, a changed name,
preserved merged bytes and unchanged recorded Device instance. Missing or
inconsistent metadata is labelled unavailable. Its original JSON stays readable,
and the tool link is withheld. The browser independently validates the projected
shape, point family, Unicode/byte bounds, encoding and scope.

**Open point tools** requires a selected controller. It opens the current
**Points & I/O → Live points & configuration** view, where the user chooses the
actual point. It never selects the historical target or point, fills a proposal,
replays a token or restores a confirmation. Normal reads after opening that view
belong to the current selected controller and interface. Without a controller,
the evidence remains readable offline and the link explains the needed selection.

Qualification includes a genuine authored-peer point-name transfer followed by
restart, sealed receipt preservation, pure local HTTP/query/search with field and
backup readers forbidden, malformed profiles/bindings, graph/CAF/History entry,
phone layout, exact original JSON download and current routed-controller
navigation. The navigation boundary explicitly authors its HTTP connection,
identity and inventory responses while the actual backend bus remains closed.
No compiler, transfer, native receipt format, prior stylesheet or physical-device
acceptance change is part of this slice.
