# Contextual binary terminal workflow

`UI-NATIVE-BINARY-TERMINAL-001` adds Move a configured binary input inside the
existing Points & I/O input configuration task. It reuses the selected retained
capture, authoritative controller route and native credentials. The analog form
is hidden while binary work is open and its exact unfinished text remains in its
existing draft. No new global destination, address entry or graphic style is added.

The binary view independently requests the explicit profile-3 source and admits
its root/capture/format, configured inputs, free slots, state labels/index,
optional polarity and historical counters. An imported capture without a redundant
Device field in its identity can still support an offline copy using its typed
native root; it does not gain field identity authority. Unknown configurations
remain visible as unavailable choices and cannot produce a proposal.

## Local and field work

Review local binary terminal copy and Save native binary terminal copy operate on
the selected captured native application. Exact source/guard/object/reference,
state labels/polarity, terminal pair, preserved charset/payloads, compiler seal
and the full original review-document seal must match. Original numeric tokens
remain authoritative. Saved native bytes must match the reviewed output hash;
Save binary terminal review downloads the unchanged response bytes. The open
graph/CAF remains separate from the native capture.

Review binary controller change appears only for the exact selected connected
controller. Its one-use review, operation ID, capture, target, identity, expiry,
compiler and original document are independently checked before confirmation.
All three wiring, unchanged binary configuration and transfer/restart confirmations
are required. Source/draft/task/lifecycle changes retire the review and cancel
its retained operation; late HTTP or cryptographic completion cannot revive it.

Apply verifies its receipt's exact operation/review/capture/edit and stored binary
configuration. Current counter values may differ from the earlier review as the
backend profile explicitly permits. Verified display additionally requires
operational status, typed preservation and unique matching published binary
configuration. Inconsistent or incomplete evidence never becomes verified success.
Unknown outcomes retain the original receipt and offer Read back binary transfer;
readback never resends the application. A pending receipt blocks another field
review. Save original binary transfer evidence preserves original JSON bytes.

A verified binary transfer marks the old capture stale for further controller
changes in both binary and ordinary input views. Capture native inputs again
before another field change; historical local copies remain available. Recorded
binary transfers reopen within their own task rather than the older analog-only
receipt controls. Drafts and evidence are bounded to 32 source/workspace contexts.

## Lifecycle and design

The existing source selector, captured/selected target, task navigation, offline
entry and parent draft remain authoritative. Local source/copy/evidence work
excludes competing input actions while allowing workspace navigation. Field
operations retain the application's global operation lock. Component teardown
releases only its own busy state; an old response cannot release a newer operation.
Errors provide explicit source reanalysis, and the existing teal/neutral styling,
engineering controls and progressive proof details remain unchanged.

This is the contextual front end for the separately qualified backend profile.
It does not expand native compilation, binary allocation/electrical configuration,
SA/IOM/cross-host/dedicated-BI moves, general rollback or physical/CCT/BTCVT
acceptance. Recorded binary Changes/History metadata and independent capability
reporting remain separate deliveries.

## Verification

Authored graph/CAF and desktop/phone cases exercise exact local/review downloads,
raw analog draft retention, binary navigation drafts, malformed source/review/
export evidence and delayed responses/digests. Owned direct/routed UDP controllers
exercise the web review, all confirmations, application transfer, published
readback, a lost acknowledgement and reconciliation without a second download.
Closed receipt cases reject malformed configuration, profile, guard, identity,
terminal, pending state, duplicate/mismatched publication and failed preservation.
Older input, analog terminal and recovery workflows remain in regression checks.

Initial tests caught a local preview unnecessarily locking workspace navigation;
only field operations now take the global lock. The initial failure remains in
local reports. No live-site, VM or Bluetooth operation is part of this delivery.
