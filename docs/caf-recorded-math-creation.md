# Recorded Math CAF creation

`FMT-CAF-MATH-COPY-001` copies one actual version 1.0 Math primitive and its
three or four port objects into a separate local CAF. The class/type-561 parent
retains properties 75/32527/518/3184/3670. Setup uses enum set 288; the recorded
Setup/StandardName pairs are 12/42, 13/43, 14/41, 15/40, 17/58 and 18/59.
The writer preserves those codes without assigning undocumented operators.

The output is class 527/type 2 at port 85. Class 526/type 2 inputs are ports
7000/7001 and, for the recorded extended setups 15/17, port 7002. The extra
input retains its standard-name code 0 in enum set 433. All observed ports are
exposed in the original array order. Children retain their root object order:
85/7000/7001, 85/7000/7002/7001, 7002/85/7000/7001 or 85/7002/7000/7001.
In particular, the output need not be the first child.

The primary inputs retain missing Float defaults, Float defaults without
metadata, or the recorded Float-plus-enum-661 schema. Missing defaults stay
missing; stored decimal spelling stays exact. Additional-input metadata is
separate from operator meaning. Unknown setup pairs, schemas, port order,
framing or modified-state bookkeeping are refused.

## Local preservation and review

The existing lexical clone path now accounts for the actual child count and
finds the output by its recorded port. Four or five local identities must fit
the unchanged allocation ceiling, including the last child. Each child retains
its type and hierarchy. One member, execution entry after the prototype and
layout record are added. Exact position text retains the finite Float32
coordinate contract.

Original objects, connections, continuations and unrelated graph properties
remain exact. The new block is unconnected. Independent parsing verifies the
expected graph, child order, configuration and original records before export.
ZIP metadata, including zero external attributes, remains preserved. Raw ZIP
compression bytes are not claimed unchanged.

Strict token-protected routes are `/api/caf/{id}/math-copy/source`, `/preview`
and `/export`. The selection binds source, diagram, prototype and every child,
including configuration, output position and four/five-ID mapping. Creation
proof binds every new child artifact hash in source order and the actual output
hash. Review, source, creation and artifact headers plus exported bytes must
agree. Client admission independently checks size, setup pair, port order,
types, references, exposure, recorded defaults, metadata and output mapping.
Requests cannot supply alternate configuration or authority. No Apply route or
field plan is introduced.

## Existing Program workspace

Open a CAF and select **Program → CAF file → Logic → Copy a recorded Math**.
When several supported families exist, **Recorded block type** selects one
focused task. Constant-only diagrams retain their existing labels. Inspect the
prototype and expand **Recorded math inputs** for actual defaults, omissions
and the extra input's metadata. Enter coordinates, review and save a separate
CAF. The reviewed result identifies four or five objects. The original review
JSON remains separately downloadable. Reopen the copy to use the existing
guarded connection editor with the new member.

Constant, comparison and Math drafts share the existing 32-context cache
without eviction. Passive inspection consumes no slot. Source, prototype,
kind, controller, task, lifecycle and visibility changes retire reviews and
late results while retaining unfinished text. Ordinary CAF Save and graph
geometry keep their existing contracts. The controller entry path retains its
selected route and separate local-file provenance.

## Evidence and remaining scope

All 156 private Math templates copy and read back in memory: 135 have three
children and 21 have four. Seven place the output after another child. All 369
earlier constant/comparison selections, reports, seals and artifact bytes match
PR229 exactly. Seven private originals stay unchanged; no derived private CAF
is saved or committed.

Authored complete expected XML covers the six setup pairs, four root child
orders, missing/plain/metadata defaults, allocation boundaries for both sizes,
unchanged wires and metadata, repeated copies and the existing connection
export. Separate API and browser checks cover source/review/artifact proof,
output mapping, mixed drafts, stale results, Unicode, compact controls and both
entry paths. The local qualification report records source/installed test,
package and preservation evidence.

This qualifies local structural copying. Operator evaluation, live values,
vendor allocation/reserved IDs, memory/scan resources, arbitrary authoring,
native File-3 compilation, CCT reopening and physical/BTCVT transfer remain
unqualified. General compiler/new-object/download flags grant no broader
operation. JCI-02, JCI-03, JCI-06 and JCI-09 remain partial.
