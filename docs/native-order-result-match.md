# Compare a retained execution-order result

In **Program → Native backup defaults**, inspect a retained source's native
diagram, choose the execution-order operation and inspect its effective order.
Select **Selected controller** as the destination to open the existing transfer
and receipt tools; the local comparison works with no field interface open.
Load an original execution-order receipt, open **Compare retained execution-order
result**, then choose **Compare retained source with recorded execution order**.

The original recorded diagram must be present and readable in the selected
retained source. The tool reconstructs the original result from its pre-transfer
Files3/11/12, recorded order edit/configuration guard and complete compilation.
The original identity, route and full compiled/native payload hashes must agree.
The selected historical proof must bind that intent, verified native application,
preserved identity, exact permutation, widths and wire relationships. Inconsistent
or unavailable originals refuse comparison.

## Separate recorded facts

The view compares original and current retained evidence separately:

- Exact original route and recorded identity.
- Expanded archive application and effective saved application.
- Original saved-directory bytes, independently of effective equivalence.
- Diagram class, member/record object identities and the complete execution order.
- Original Unsigned payload widths and recorded wire relationships.

A match requires all of these comparisons except byte-identical saved-directory
layout. Re-encoding an archive can preserve expanded/effective equivalence while
changing its original file hash. A saved-value change can leave its archive/order
unchanged while changing the effective application. An actual different route or
coherent renamed native identity remains a difference even with identical order.
No point inventory or program is selected by model name.

The first immutable verified readback remains usable when a later observation is
unknown. Its kind and time appear as historical evidence. Loading that proof does
not rewrite the original receipt, replace the latest outcome or enable a fresh
write. Pending unresolved transfers still require their existing readback path.
The unchanged transfer validator is reused on a private selected-observation view
solely to qualify this read-only comparison.

The browser independently checks the original receipt/proof bindings, current
source report, original/effective selections, comparison arithmetic and response
seal before displaying or exporting evidence. **Save exact execution-order
comparison** preserves the verified original response bytes. Source, diagram,
receipt, proposed draft, destination/mode, task and page lifetime retire pending
results and cached callbacks. Cancellation retires the local response; it sends no
native cancellation or recovery request. Unfinished order, CAF and graph drafts
remain independent of the retained source being compared.

## API and scope

`POST /api/bacnet/controller/native-application/execution-order/result/compare`
requires the existing local session token and exactly `receipt_id`, `capture_id`
and `snapshot_sha256`. Profile `native-execution-order-result-match/1` returns a
sealed historical report in state `application-and-order-match` or `different`.

Comparison reads retained local evidence. It creates no capture, receipt, journal
event, review token, compilation artifact, recovery proposal or field authority.
It sends no controller query or command, changes no credential or original file,
and establishes no current-device, CCT/runtime, broad compiler/package/resource,
physical or BTCVT acceptance. Other transfer-result families and whole-state
migration remain separate work under JCI-01/JCI-10.

Qualification uses actual order transfers/readbacks on authored localhost peers,
original archive formats, direct/routed retained sources, coherent identity and
saved/order differences, resealed/tampered evidence, offline CAF/graph workflows,
compact layouts, exact exports and source/receipt/task/lifetime retirement.
