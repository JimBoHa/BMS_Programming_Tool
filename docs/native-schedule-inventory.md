# Native BACnet Calendar and Schedule inventory

Connect → **Native Calendar / Schedule inventory** inspects standard Calendar (object type 6) and Schedule (17) objects on one explicit, identity-verified Device. This read-only profile prepares later native editing; it does not edit, compile, download, run, simulate or restore a controller schedule. It is separate from Studio's portable graph Schedule block and its IANA timezone evaluator.

Open the BACnet/IPv4 interface first. Enter the exact Device identifier and either its IPv4 endpoint or an explicit IPv4 router endpoint plus matching DNET:MAC. Choose up to 16 Calendar/Schedule identifiers, separated by semicolons or newlines. Alternatively leave the selection empty to read one bounded indexed Device Object_List page. Offset is the number of list elements skipped, so offset 0 begins at array index 1. A returned next offset is a suggestion for another explicit request, not a stable continuation token. A changing Object_List can repeat, remove or move objects between reads. Referenced calendars, target properties and other devices are retained as references and are never automatically read.

The Device and each selected object must return their exact Object_Identifier before that object's schedule properties are read. The report retains Object_Name, Description and Present_Value, Calendar Date_List, and Schedule Effective_Period, Schedule_Default, Priority_For_Writing, List_Of_Object_Property_References, Status_Flags, Reliability, Out_Of_Service, Weekly_Schedule and Exception_Schedule. Weekly and exception arrays use index 0 for the count, then bounded individual indexes. Each property/index has its own status and receipt time; native Error/Reject/Abort, timeout, wrong identities, opaque/decode failures and limits are distinct evidence, never invented empty or valid schedules.

Native TimeValue AnyAtomic values preserve primitive datatype, value and tag evidence. Calendar date/date-range/weekNDay and exception CalendarReference choices remain native. Raw Date/Time fields retain wildcard and special field values; unknown enums retain their numeric code, and unknown AnyAtomic application choices remain opaque evidence. No wildcard is turned into a guessed date. Optional Device Local_Date, Local_Time, UTC_Offset and Daylight_Savings_Status remain raw fields. Their clock is not resolved to local UTC or an IANA timezone. Priority_For_Writing and referenced array indexes are evidence, not permission to write.

## Evidence and limits

On the pinned Windows shared IPv4 socket, the [owned receive provenance profile](ipv4-receive-provenance.md) establishes the bound socket, exact peer and raw BVLC Original-Unicast frame while preserving native broadcast destination metadata. Its physical IP destination is unavailable; this is not a kernel-level unicast-destination claim.

Each operation has a source/configuration snapshot, local UTC start/end and property receipt times, exact response identity checks, per-property tag re-encoding hashes and bounded matching UDP transport candidates. Candidate UDP bytes are original received bytes; property-tag hashes identify BACpypes3 tag re-encoding and are explicitly not packet-capture hashes. A matching transport candidate can still be malformed and is not proof of a valid response. The actual peer, local endpoint and routed NPDU source are pinned independently of mutable route caches. Forwarded/broadcast responses are outside this Original-Unicast profile. Unrelated native packets/observers are preserved.

Reports are sequential live observations. Even a report marked complete means only that its selected fields/page were successfully read; it does **not** establish an atomic device snapshot, consistent backup, frozen schedule or current referenced-device assignment. A native device may change between properties. Physical JCI/other manufacturer and firmware acceptance is unverified.

The shipped bounds are one active operation, 15 seconds including interface-lock acquisition, 1 second per ReadProperty, 20 ms request pacing, one transmission per owned request, 1,024 requests, 16 selected objects, Object_List counts up to 20,000 and pages up to 256, at most 32 entries per exception array, 16 KiB retained encoded property values, 4,096 tags/items and 16 levels, 64 KiB per property record, and a 2 MiB report budget. The native transport may reject an oversized/malformed APDU before a property decoder receives it; such a failure is not represented as an empty value. Segmented responses are not assembled by this profile; indexed reads reduce response sizes, but a large Date_List/DailySchedule/references value can still remain unavailable. No automatic retries, next pages, reconnects, scans, subscription or edits occur.

Cancellation, shutdown, interface/configuration/socket replacement and finite deadlines retire owned transactions and temporary hooks. Completed property/index evidence survives cancellation, including a partially read array. A cancel received before admission tombstones that operation ID. Reports retain their original source when reopened; late reads/exports are invalidated by selection/source/draft/navigation changes.

Only the last 16 immutable reports are retained in application memory. **Export exact schedule evidence** before restart or eviction. Export saves the exact authenticated server JSON response, preserving signed zero and integral-float spelling that browser JSON previews normalize. Its `evidence_sha256` is SHA-256 of UTF-8 `json.dumps(body, sort_keys=True, separators=(",", ":"), allow_nan=False)` after removing only `evidence_sha256`. Reopening and exporting retained evidence cause no network queries. Restart retains no schedule reports and opens no field interface. Durable schedule archives, native editing, reviewed property writes/transfer, segmentation, direct serial and BBMD delivery are followups.

## Source contracts and manual scope

Reviewed primary implementation contracts are the pinned installed **BACpypes3 0.0.110** `object.py` (CalendarObject/ScheduleObject/DeviceObject), `basetypes.py` (CalendarEntry, DailySchedule, TimeValue, DateRange, SpecialEvent and DeviceObjectPropertyReference), `constructeddata.py` (AnyAtomic, Array and Sequence) and `primitivedata.py` Date/Time/tag contracts. Upstream source is [BACpypes3](https://github.com/JoelBender/BACpypes3); runtime behavior is checked against the pinned local release, not inferred from a future main branch.

These describe calendar/weekly/exception/target/clock functions used to define inventory requirements. Niagara station CalendarSchedule components are not equated to standard BACnet objects. JCI proprietary output behavior, calendar cleanup, archive editing and vendor timezone settings are not inferred. Broad manual features MF-e39fd7dcb6, MF-3964cbd0c0 and MF-9030e4190e remain partial: this PR implements inventory/evidence only.

Validation uses independently authored literal BVLC/NPDU/APDU response bytes over real local UDP, direct and explicit routed paths, HTTP and actual Chromium downloads. It covers wildcards, signed zero, integral floats, unknown AnyAtomic/enums, native errors, malformed/late/rogue responses, finite bounds, cancellation, interface loss, observer composition and restart. It does not contact site equipment or prove physical MS/TP timing, controller support or electrical behavior.

Per-property receipts also retain [owned dispatch and reply diagnostics](property-dispatch-diagnostics.md). Local handoff timing does not establish socket transmission or device processing latency.
