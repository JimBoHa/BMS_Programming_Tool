# Local previous-terminal proposals for configured analog inputs

`FMT-NATIVE-ENCODED-ANALOG-RECOVERY-001` adds the local API
`/api/bacnet/controller/native-application/input/encoded-terminal/recovery/prepare`.
Its strict request contains a retained receipt ID, current capture ID and snapshot
hash. It derives a previous-terminal proposal from an original profile-4 transfer;
it does not query a controller, retain a plan or apply a change.

Preparation requires a resolved historically verified result or immutable verified
readback, possible original dispatch, exact identity/confirmations and complete
profile-4 native preservation. The original native files and saved settings must
reconstruct the canonical original edit, compilation and payload hashes exactly.
Earlier analog/binary profiles cannot supply this recovery proposal.

The current retained capture must match the original controller, route, identity
and static directory. Its native application must be the recorded after image or
the original effective image. The selected input/reference/terminal and typed
configuration/field presence must remain unchanged. A fresh configuration guard
binds the proposal. The inverse compiler preserves the current ASCII/UCS-2 label
encoding, paired absent output endpoints and other current saved values. It moves
only the selected input back to its previous recorded universal terminal.

The sealed report includes original/current lineage, verified proof, a proposed
canonical edit, inverse compilation/output hash and explicit read-only/no-authority
flags. If the previous binding is already recorded, the report contains no inverse
or proposal. Original receipts and source files remain unchanged; unresolved,
unverified, mismatched or unsupported evidence cannot supply a recovery proposal.

This delivery is backend preparation only. The response grants no field token,
parent-enforced transfer authority or automatic rollback. A separately qualified
field review and contextual web workflow remain next, with a fresh current capture,
all confirmations, one-use transfer and complete native/published readback. General
application restore, allocation/electrical edits, SA/cross-host moves, packages/
resources and physical/CCT/BTCVT acceptance remain separate. IO-02/JCI-09 remain
partial.

Verification uses independent complete-image expectations across ASCII/UCS-2,
native/compressed containers, record widths, terminal payload widths and present/
absent linear endpoints. It preserves unrelated current saved values and covers
already-recorded state, later verified readback, original/current mismatches,
changed saved configuration, malformed typed preservation and disconnected HTTP
preparation with field/intent paths forbidden. Earlier recovery and transfer
families remain in regression coverage. No private inventory is embedded.
