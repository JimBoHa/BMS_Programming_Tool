# Matching native connections in the controller workspace

`UI-NATIVE-CONNECTION-TRANSFER-001` connects the separately qualified
[matching-connection transfer service](native-matching-connection-transfer.md)
to the existing Program task. It adds one matching connection between existing
native members. It does not create blocks, points, terminal assignments or a
general native program.

## Use the existing connection task

Open a controller, then choose **Program → Native backup defaults**. Capture its
native application explicitly, inspect a diagram and choose the matching
connection operation. Select the saved-effective connection basis, an
observed prototype, an output member and an unused matching destination.

**Matching connection destination** defaults to a local file. This retains the
existing archive-copy and saved-effective compilation workflows, including exact
review downloads and local output verification. Select **Apply to the selected controller**
to prepare a field transfer. The task reuses the selected controller's exact
interface, address, router, network and Device identity. A source captured from
another controller cannot authorize this transfer, even when its Device instance
matches. Retained applications remain useful offline for local work.

Configure native credentials in the contextual credential disclosure if needed.
Opening the task or loading history neither opens an interface nor captures an
application. Capture and readback may enter and end backup mode. Apply can
interrupt control. The supported transfer interface is already-open plain
BACnet/IPv4; other transports remain separately qualified work.

## Review, apply and verify

1. Choose **Review matching connection transfer**. The client checks the returned
   profile, authoritative target, capture, source/effective hashes, prototype,
   selected endpoints, guard and compiler/preservation bindings.
2. Review the source, destination and connection count. Confirm the existing-member
   connection and unused input, then confirm the application transfer and possible
   control interruption. Exact review JSON is available for download.
3. Choose **Apply matching connection to controller**. The backend owns the
   one-use review, fresh configuration/capacity checks, saved-value preservation,
   durable original/payload/intent, single restore and complete readback.
4. A verified receipt identifies the appended edge and unchanged identity. Choose
   **Open verified application snapshot** explicitly to inspect its retained
   readback. The task does not silently replace the source or discard a draft.

The active task has one primary action. The existing teal styles, engineering
tables, disclosures, compact navigation and keyboard controls remain in use.
There is no new top-level destination.

## Drafts, cancellation and uncertain outcomes

Source/prototype/pair drafts and the destination preference use the existing
bounded, non-evicting wire cache. Switching tasks or connection modes preserves
local work while retiring its review. Target, interface, source, proposal,
visibility and other owned field-operation changes also retire review authority.
Late replies cannot revive a retired plan. Cancellation addresses only this
task's owned operation; an old completion cannot release a newer busy owner.

An uncertain operation stays attached to its original controller and operation
ID. Load its retained receipt and select that exact original target/interface
before choosing **Read back matching connection**. Readback observes the existing
operation; it never replays its restore. The existing server-wide pending-native
guard blocks new engineering work until the retained operation is resolved.

Full original-image/settings recovery is displayed separately from verification
of the added edge. A malformed reply cannot claim success. Keep the original
receipt and use explicit receipt loading/readback after transport or response
failures. Historical original results remain present when later readback resolves
the outcome.

## Recorded evidence and capability scope

Changes and History display known recorded source/destination references,
prototype/new tuples, connection counts, compilation hash and confirmation.
Original receipt JSON remains downloadable. **Open native program tools** opens
the existing Program tool while preserving the current workspace target and local
CAF. It does not adopt the historical station, validate an original backup,
prepare a new review or send a controller request. Invalid or future metadata
keeps raw evidence available and withholds its interpreted program shortcut.

The capability panel requests explicit profile 13 and displays its 25 operations.
The existing default/explicit profile 12 and legacy profile 11 backend contracts
are unchanged. A preflight row is source evidence, not current device acceptance.

Authored direct/routed UDP peers qualify software review, restore, readback,
recovery, context retirement, recorded evidence and browser behavior. They do not
establish physical or BTCVT acceptance, arbitrary native compilation, runtime
semantics or vendor package/resource support. JCI-03 and JCI-09 remain partial.
