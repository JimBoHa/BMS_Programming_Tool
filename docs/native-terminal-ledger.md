# Recorded terminal moves in Changes and History

`HIST-NATIVE-TERMINAL-001` adds a separate, strict projection of recorded native
input operation profile 2. It leaves the complete older input metadata parser
unchanged. Changes and History use the same journal and existing navigation.

Rows show the analog input and previous/destination UI terminal labels. Details
show the exact native reference, preserved recorded configuration, recorded wiring
confirmation and source/output/compilation fingerprints. Configuration numbers
retain native Real32 values and signed zero. Setup and unit values remain recorded
codes; the view does not invent an electrical mode or current measurement.

The backend requires the exact terminal action, operation/compiler/inner-copy
versions, typed options, matching object/reference/terminal labels, unchanged
record counts, two non-overlapping fixed-width payloads, preservation flags and
the sealed inner compilation. Source/output digests bind the saved merge and
recorded native/container payloads. Malformed bindings, foreign versions and
inconsistent configuration retain original evidence while structured metadata
stays unavailable. Explicit terminal metadata never falls back to a supplied
legacy input record.

The browser independently checks the exact metadata shape, profile, labels,
reference, finite native values, fingerprints and absence of extra authority
fields. Valid metadata can open the existing local **Open input tools** route.
It preserves the current controller/file and does not select the historical
controller, stage a move, restore a token, retry or reconcile an operation.
Profile-2 field controls remain a separate delivery.

Listing, filtering, viewing and exporting remain local. They do not reopen
backups, validate parent/source records, query a controller, run native backup
state commands or create a transfer plan. The historical wiring confirmation is
not current wiring/accuracy verification. **Download evidence JSON** retains the
original source endpoint response bytes even when structured metadata is refused.
Existing scope, outcome, target/interface, journal and redaction rules remain.

Checks use actual native terminal transfers to authored loopback controllers,
then reopen their stores through a disconnected app with field/source access
replaced by failing sentinels. They cover malformed/resealed bindings, older
profiles, exact downloads, Changes/History, compact layout, local tool navigation
and rejection of an injected legacy fallback. No site, VM or Bluetooth operation
is part of this recorded-evidence profile.
