# Prepare previous effective typed batch defaults

In **Program → Native backup defaults**, open the intended retained backup and
expand the typed batch task and controller workflow. Load the original batch
receipt, then choose **Prepare previous batch defaults**. Preparation reads local
retained evidence and displays previous, recorded-after and retained-current
values. **Save exact previous batch proposal** exports the original JSON response.
Ordinary unfinished drafts remain separate and are never replaced.
Unresolved receipts, receipts with no possible restore, and receipts without a
retained verified outcome explain why preparation is unavailable.

Read a current native backup separately when needed. That existing capture enters
and ends backup mode. Preparation itself performs no controller query, command,
field review, retained plan or journal write. It remains useful offline. The report
contains a hypothetical compilation and output hash, not a downloadable controller
application or an executable field plan. A separate
[fresh lineage-bound controller transfer](native-default-batch-recovery-transfer.md)
can review and deploy the derived previous values. Preparation itself grants no
field authority.

## Original evidence and current source

Profile `native-default-batch-recovery-draft/1` requires a resolved native typed
batch receipt with a possible original dispatch and an immutable verified result
or historical verified readback. A no-dispatch refusal cannot gain recovery support
from a later readback. Uncertain original operations must be reconciled first.
A later inconclusive observation does not erase an earlier immutable verified
readback. The receipt view can load that historical proof for local preparation;
it supplies no new current-device verification or field authority.

Original Files3/11/12, selected guards, the entire recomputed compilation and both
payload hashes must agree. Prior values come from the original effective saved
merge, which may differ from archive defaults. The current retained source must
have the same exact route, Device identity, expanded native application and static
saved directory as the recorded outcome. Gzip recompression may differ; changed
application configuration or saved-directory compaction requires separate
engineering. Every selected current value must equal its recorded result or its
previous value. Third values are refused.

Real restoration preserves finite float32 bits, including signed zero. Booleans
remain strict typed values. Enums require unchanged actual fixed saved storage and
recorded state-text encoding; numeric meanings or set membership are not inferred.
One to sixteen originally selected fields retain source order. Other current saved
settings remain current through the existing independent typed compiler.

If all prior values are already present, the report creates no proposal or
compilation. This is an observation of retained files, not a live-state claim.
Partially restored batches retain the complete original selected set and report
the actual changed count. Parent receipts, original backups and current
capture files remain unchanged.

## Browser and API

The browser independently checks the original supported receipt, exact report
schema, source and parent bindings, historical proof, selected typed values,
origin seal and existing compiler evidence. Exact JSON downloads retain the
received bytes. Current source/task/editor generation, visibility and operation
ownership retire late results and download handlers. The existing teal layout,
two entry paths, keyboard table scrolling and unfinished drafts remain intact.

`POST /api/bacnet/controller/native-application/default-batch/recovery/prepare`
requires the local session token and exactly `receipt_id`, `capture_id` and
`snapshot_sha256`. Existing batch transfer request/confirmation/receipt contracts
remain independent. The separate recovery transfer accepts only a parent receipt
and origin hash, rederives the full report, and requires a fresh controller review.

This profile completes local previous-value batch preparation only. Recovery
deployment has its separate qualification. General rollback, new blocks/I/O,
native package/resource/runtime/CCT comparison and physical/BTCVT acceptance remain
separate. JCI-10 remains partial.
