# Captured-source combined operation support

In **Program → Native backup defaults**, select a retained source, inspect the
original backup and open **Operation support for this native backup**. Opt into
**Include combined default/connection and terminal operation support** to include
the existing terminal operations and two separately qualified combined rows in
the same table. The ordinary view remains available. No interface is opened and
no current controller state is verified by either view.

The extended analysis reads the original, integrity-checked Files 3/11/12. Actual
recorded identity, supported Real fields, saved selectors/values/checksums and
native graph content qualify a hypothetical pair. Model names do not supply
blocks, inputs, graph structure or compatibility. An unreadable saved layout can
leave archive inspection available while making combined compilation unavailable.

## What the two rows establish

**Compile an existing Real default and connection together** requires an actual
paired compilation. Both existing narrow compilers must qualify the same saved
merge. The joint compiler reparses both composition orders, compares their
complete outputs with the two original disjoint byte patches and preserves every
other expanded byte, record membership and identity. The retained witness keeps
the literal source, selection and compilation reports with their original profiles.

The witness changes one actual class 526/527 Real Default Value and an existing
connection's source. Its hypothetical value is `1` when the selected effective
bits are positive zero, otherwise `0`; both selected fields must change. This
does not replace the operator's selected value or stage an editor draft. It does
not return a local export review seal, field token, output file or transfer intent.
Use the [combined editor](native-combined-default-wire.md) to choose the intended
edits and explicitly review a local copy.

Search considers the first actual qualified existing connection and alternate
source, then at most sixteen supported Real fields. The reported attempt count
and limit remain explicit. An unsuccessful paired probe reports **not evaluated**;
it does not prove every other pair is impossible. Missing supported Real fields,
unqualified saved structure or no qualified alternate connection can report
**unsupported source**, with the actual bounded error retained.

**Review a combined Real default and connection transfer** additionally checks
native omitted-field type qualification and the captured transport profile. A
valid local pair can coexist with unavailable transfer qualification. Recorded
plain IPv4, including an explicit router/network/station route, establishes only
**preflight required**. Serial/foreign-device captures can retain local support
while reporting **transport unavailable**. Identity contradictions remain distinct.

The [combined field task](native-default-wire-transfer.md) still requires its own
fresh identity/interface/default/graph/settings/capacity review, confirmations,
one-use Apply and complete native/effective readback. This table never supplies
that authority. Package/resource validation, native execution, CCT comparison,
physical wiring and physical controller acceptance remain separate.

## Ownership and evidence

The table retains the existing teal controller/file layout and readable operation
rows. Its viewport supports keyboard focus and horizontal scrolling on smaller
screens. Source, route and requested analysis mode remain bound to results and
exact JSON downloads. Mode changes retire old results and downloads synchronously,
including A→B→A changes before repaint. Late results cannot replace a newer mode.
Native editor drafts remain intact; analysis never writes their values.

**Save exact operation analysis** downloads the admitted original response bytes.
Detailed qualification keeps the actual hypothetical field, connection, input-file
hashes and independent/intermediate compiler reports. Recorded capability evidence
does not establish current values or a live connection and does not create a
transfer/recovery receipt. Keep it separate from actual deployment verification.

## API and compatibility

The session-token protected endpoint remains
`POST /api/bacnet/controller/native-application/inspection/capabilities`.
Explicit `capability_profile: "native-backup-operation-capabilities/19"` returns
36 ordered operation rows and a `combined_default_wire` qualification object.
The first 34 rows and previous qualification entries match explicit profile 18.
Profiles 11–18 and the API default, profile 12, retain their earlier behavior.
The ordinary main table continues requesting profile 14 unless the user opts in.

The response retains `read_only: true`, `controller_queries: false`,
`field_actions: false`, `can_apply: false` and
`current_identity_verified: false`. The client validates the complete previous
profile, original capture/files/route, actual source/selection, both changed edits,
literal composition proof and separate type/transport statuses before display.
A shared pure compilation predicate checks report consistency; the original local
review validator still separately requires its source envelope and review seal.

Qualification uses authored framed native records and saved bytes, literal byte
deltas, actual disconnected UDP capture, strict HTTP admission and source/installed
Chromium/WebKit workflows. Original files remain unchanged and analysis sends no
additional peer requests or transfer journal entry. These are software/source
checks. JCI-01, general native compilation and physical acceptance remain partial.
