# Review and apply an existing analog terminal move

`UI-NATIVE-INPUT-TERMINAL-TRANSFER-001` adds **Move a configured analog input**
to the existing Points & I/O input-operation selector. Select an existing analog
input and a configured free universal destination on the same controller. The
view shows the captured previous terminal and proposed destination, and keeps
electrical mode, scaling, identity and program connections unchanged.

This uses the separately qualified [native input transfer profile 2](native-terminal-transfer.md).
Older allocation, electrical-mode and remove-app-allocated actions retain their
profile-1 paths. The separate original/saved-effective local terminal-copy task
also stays available. No new global destination, tile, style or canvas is added.

## Local work

A retained source can be opened offline from graph or CAF entry. **Review local
input copy** and **Save native copy** create a separate saved-effective native
file; no field interface, plan or write is acquired. The open CAF stays separate.
Changing the draft retires its copy review, and task navigation retains local
selection while requiring a new review. Existing workspace draft bounds remain.

## Field work

Open the exact controller/interface and capture its native input source. A field
review requires the captured input/configuration guard, original route and free
destination. Unsupported native bindings remain explicit errors; they do not
gain an Apply button. Integral sensors, binary field moves, SA/cross-host and
dedicated binary terminals are outside this profile.

The review displays both terminals and preserves the current native configuration.
The client checks operation/compiler/inner-copy versions, exact typed edit,
identity/target/capture, preserved configuration, counts, payloads, digests and
the sealed inner compilation. It additionally verifies the complete native
review seal from its original JSON numeric tokens. This retains floating-point
spellings, signed zero, large integers, Unicode and Python key ordering rather
than hashing a lossy JSON parse/stringify result.

Apply remains disabled until all three wiring, unchanged-mode terminal-move and
application-transfer confirmations are checked. The existing backend enforces a
one-use plan and fresh source/published configuration/capacity/identity/expiry
checks. Applying transfers the native application and can restart control.
Whole-image, saved-setting and published-input verification remain required.

Unknown outcomes keep their original receipt and expose explicit **Read back
input transfer**. Readback can run native backup state commands but never sends
the reviewed program again. It does not restore or automatically reverse a move.

## Ownership and verification

Source/target/interface and draft changes retire pending reviews and acknowledgements.
Unmount, page hide and visibility changes also retire them. Asynchronous numeric
and digest validation rechecks ownership before publishing a review, so a delayed
digest cannot resurrect an old plan. Invalid proof cancels its retained review.
Receipt admission pairs terminal action/profile 2 and older actions/profile 1.

Checks use owned direct/routed loopback controllers, offline graph/CAF sources,
exact native-copy downloads, malformed proofs, all confirmations, unknown outcomes,
explicit readback without another download and delayed-response/digest retirement.
No live-site, VM or Bluetooth operation is part of this software qualification.
Actual rewiring, CCT/controller physical acceptance, general native compilation,
resource/package qualification and broader hardware reassignment remain separate.
