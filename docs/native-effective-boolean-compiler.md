# Effective native Boolean default compiler

In **Program → Native backup defaults**, inspect a retained archive's actual
Boolean record. Set **Boolean default source** to **Merge retained saved
settings**, then **Open saved Boolean defaults**. The editor shows the original
archive value and the retained effective value separately. Choose an explicit
Boolean, review the compilation and save a compiled copy or its exact review JSON.
The original archive-copy mode remains independently available.

This compiler merges actual saved Files 11/12 into the retained native File 3
before changing one existing class 530/531 Default Value (3113). It checks saved
selectors, values, checksums and coverage through the existing parameter compiler.
Retained vendor-5 acquisition identity must be verified and must agree with the
actual root Device instance, name and model. The saved merge must preserve that
identity, supported Boolean membership, engineering references and native object
IDs/classes. Current interface transport does not restrict this local operation.

The Boolean patch then changes at most one canonical application-tag byte in the
merged application. Output reparsing checks every other merged expanded byte.
Other retained saved values remain merged, including other Boolean defaults,
numeric values and values whose encoding changes record lengths. Original Files
3/11/12 are immutable. An unchanged selected effective value can still produce a
file that differs from the archive because other saved settings are merged; the
review states that boundary explicitly.

Unknown saved layouts, checksum/coverage problems, identity disagreement or
reassigned references refuse effective compilation. These errors do not remove
the separately qualified [archive-only copy](native-boolean-default-copies.md).
Neither local mode performs a controller query, backup-state command, native
transfer or journal insertion. Retained effective values are historical settings,
not fresh live measurements or proof of physical acceptance.

Archive and effective proposals use distinct baseline/source namespaces in the
existing bounded in-memory Boolean draft cache. Switching modes, records, captures
or tasks retains local proposals and retires reviews. The source loader and editor
bind capture/manifest/archive/merged/property identities, original/effective values,
exact station and strict operation flags. Delayed source/review/export replies
cannot return after a mode or source A→B→A change. Output bytes and review JSON
retain their independent digest and original response.

Token-admitted endpoints under
`/api/bacnet/controller/native-application/boolean-default-compiler` are
`POST /source`, `POST /preview` and `POST /export`. The profile is
`native-effective-boolean-default-compiler/1`. Source takes capture ID and manifest
hash; preview additionally takes original archive hash, reference, effective
property-encoding hash and a strict JSON Boolean. Export also takes the review
hash and recomputes the entire compilation. All original file hashes are checked
on each call. Response headers bind snapshot, review and actual artifact SHA-256.

Native-backup operation matrix profile 3 adds the fourteenth operation for this
effective Boolean compiler. Field transfer remains separately qualified and
currently Real-only. Arbitrary logic generation, resource/package compatibility,
hardware allocation, CCT reopening and physical/BTCVT acceptance remain separate.
JCI-02/JCI-03/JCI-09 remain partial overall.

Qualification uses complete plain/gzip and short/extended native frames, literal
Boolean tags, independent expected merged bytes, unchanged-value behavior, saved
identity/reference/CRC failures, strict local HTTP, source/property/review guards
and an authored native UDP backup disconnected before compilation. Browser checks
cover actual compiled/review bytes, separate draft baselines, unknown sources,
altered replies and late results. No site acceptance is inferred.
