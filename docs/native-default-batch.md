# Compile several existing native defaults together

Open **Program → Native backup defaults**, select and open an original retained
backup, then expand **Compile several native defaults together**. Select actual
recorded fields, enter their proposed values and choose **Review local default
batch**. **Save compiled default batch** saves the reviewed MOI copy. The exact
review JSON is separately downloadable.

This task compiles one to sixteen distinct existing Real, Boolean or Enum Default
Value fields. It retains the captured Device, route, identity and acquisition
time. These values come from the original Files 3/11/12 saved-setting snapshot;
they are separate from current controller readings and from any open CAF file.
The table reads actual field names, references, types, archive values and saved
effective values. Search, selected-only filtering and fifty-row pages preserve
all selected drafts. Narrow tables support horizontal keyboard scrolling.

## Compilation and preservation

The existing Real, Boolean and Enum compilers must qualify the same native saved
merge, file hashes and recorded identity. A model name supplies no fields or
compatibility. Their original field/profile reports remain visible. Duplicate
references, unknown kinds, stale hashes, unsupported saved layouts, invalid values
or a failed constituent edit refuse the complete local batch.

Every proposed edit first compiles independently from that shared merge. Its
reported hashes must agree with its actual output, and its expanded bytes must
match exactly one selected property replacement. The batch then constructs the
literal expected image from those disjoint replacements, retaining all other
record bytes and identities. Existing narrow archive editors independently apply
the entire list in forward and reverse order. Neither composition merges saved
values over an edited intermediate. Both complete outputs must agree with each
other and the literal expected image.

Real values retain float32 admission, including signed zero, explicit rounding
evidence and overflow/underflow refusal. Boolean proposals require actual Boolean
values. Enum proposals retain unsigned32 encoding and the original value width
when sufficient. Captured fixed saved storage bounds a code where present; without
that storage, only the local unsigned32 representation is qualified. Enum meanings,
membership and executable mappings remain unverified. All captured state metadata
is preserved.

An Enum growing beyond its old encoding width may enlarge its record and promote
only that record from compact to extended framing. All untouched native bytes,
record order/membership, graph, execution order and Device identity remain intact.
An entirely unchanged batch returns the exact merged source, which can still
differ from the original unmerged File 3. Original Files 3/11/12 are never changed.

## Draft and task ownership

Ordinary single-field drafts remain separate while the batch task is open. A
source can retain sixteen batch selections; up to thirty-two nonempty source
drafts remain in the current workspace without eviction. Empty views consume no
slot. Remove selections or explicitly **Discard this batch draft** to free work.
These batch drafts stay in memory until explicitly
[saved as unfinished batch text](native-batch-draft-files.md). The existing
single-Real session/file recovery feature remains separate.

Proposal, source, controller context, task and visibility changes retire pending
local reviews/downloads. Counters distinguish changes away and back to the same
text or task before repaint. Coalesced edits to different fields preserve both
raw buffers. Completed old previews and already-dispatched local export responses
cannot replace a newer draft or produce a stale download.

Opening/closing this task also retires the existing native default/wire application
transfer reviews through their original shared admission and ownership rules.
An old confirmed Real or Boolean Apply cannot survive a coalesced batch open-close.
Fresh reviews remain available afterward. An active controller operation keeps
the task switch locked; the batch does not cancel a dispatched write or clear an
uncertain receipt. The existing single-field/wire compilers and field profiles
retain their separate behavior.

## API and qualification

Studio-token protected local endpoints are
`POST /api/bacnet/controller/native-application/inspection/default-batch/source`,
`/preview` and `/export`. The separate profile is
`native-effective-default-batch-compiler/1`. Export reopens the immutable source,
recompiles the exact request and checks the local review seal. The browser checks
the complete source/review contract, independent typed reports, composition chains,
artifact headers and downloaded byte hash. No controller interface is opened,
field query sent, transfer plan issued or transfer journal written by this task.

Qualification uses authored mixed native records, literal property bytes,
compression/no-op/width/framing boundaries, original metadata and disconnected
captures. Source/installed Chromium/WebKit workflows exercise both entry paths,
exact files, malformed/late results, draft continuity, sixteen-field capacity and
authored localhost-controller transfer-plan retirement. These are software/source
checks. This profile adds no field Apply, new block/link allocation, resource or
package validation, native execution, CCT comparison or physical/Bluetooth
acceptance. General JCI compilation and deployment remain partial.

[Source-specific batch operation support](native-batch-capabilities.md) separately
reports actual local compilation witnesses in the existing capability table.

The separate [controller batch transfer workflow](native-default-batch-transfer.md)
now supports a guarded existing-default scope. Local compiler reviews and raw
batch files still grant no field authority; deployment requires a fresh controller
review and retains its own journal/readback contract.
