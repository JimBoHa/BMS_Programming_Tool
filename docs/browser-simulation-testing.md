# Browser calculation-session ownership

Browser tests share a local server, but Playwright context disposal does not guarantee that document-exit handlers or keepalive cleanup requests finish. A completed test can therefore leave a volatile calculation engine behind. With the intentional 25-session cache limit, later independent tests can fail even though Reset and source-change cleanup work correctly.

Tests exercising the Program simulator import `test` and `expect` from `web/tests/simulationFixture.ts`. The fixture observes only its own page's successful first-step responses. It records a handle only when the response's immutable creation-operation identity matches the random operation identity in that page's actual creating request. It stops its own page and retires only those exact handles through the public authenticated API. Retirement failures fail teardown. The fixture never enumerates the cache, increases its limit, restarts the server to conceal exhaustion, or clears unrelated engines or durable history.

This is test resource ownership, not a stronger product exit guarantee. A missing or unverifiable response is not guessed; its engine remains subject to the existing idle expiry. The explicit session lifecycle tests retain their own cleanup and continue to test reset/source/reload behavior, pending admission, unknown replies, failed keepalive and durable history separately. Production remains bounded and document-exit cleanup remains best effort.

Two ordered browser cases verify the fixture retires its page-created engine while an independently created engine remains usable. The shared clock test compares recording against its starting sample count, then expects exactly three new samples. It does not assume an empty store or delete samples left by earlier browser projects.

The unchanged integrated batch originally passed 87 and failed 13 after Chromium left completed test sessions cached before WebKit. All 13 failure contexts reported the session limit. With owned teardown, the 104-case batch passed 103 and exposed one separate assertion assuming an empty durable history store. Both Chromium and WebKit versions of that assertion passed after switching to the preserved baseline; eight adjacent macro, Niagara, notification and temperature workflows also passed. Earlier failure logs and traces remain available in the local review reports.
