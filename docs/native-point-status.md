# Native point reliability and service-state inspection

Connect → **Native point status** closes a gap in the existing one-property reader. Select one exact Device and up to 16 analog, binary or multistate input/output/value objects, or Accumulator objects. Use the existing object-list and point tools to choose identifiers; this inspector performs no discovery or automatic reference traversal.

An already-open plain BACnet/IPv4 interface is required. Supply the exact Device identifier and either its direct IPv4 endpoint or an explicit IPv4 router endpoint with matching DNET:MAC. The Device and every point must return their exact Object_Identifier before the point's remaining fields are read. Reopening/exporting a retained report does not contact a controller.

The inspector reads native Object_Name, Description, Present_Value, Units where defined on that standard class, Status_Flags, Reliability and Out_Of_Service. The optional checkbox explicitly reads commandable Priority_Array count and individual slots, and Relinquish_Default, where the pinned standard class declares those properties. A device may still reject an optional property. No optional property is assumed to exist merely because its datatype is known.

Native values retain their actual datatype and encoded evidence: analog Real, BinaryPV enum, multistate/Accumulator Unsigned, units/reliability numeric codes and known/unknown enum names, raw status flags and service-state Boolean. No engineering scaling, unit conversion, sensor range, hardware binding or operator-entered trend metadata is inferred. PriorityValue Null, typed choices and signed zero remain distinct. Slots are sequential observations, so the inspector does not infer a current winning priority, command owner, write permission, effective actuator output or coherent command vector.

**Read completeness is not health.** A finite Present_Value can coexist with fault, override, out-of-service, unknown reliability or missing native fields. The report leaves health assessment unestablished, even when a standard no-fault indication is returned. The four StatusFlags positions are in-alarm, fault, overridden and out-of-service. Independent sequential fields may disagree or change between reads. Native quality fields with malformed encoding are unknown: BACpypes3 can pad a short StatusFlags value or normalize a nonzero Boolean tag; this profile retains original tag/bit evidence without presenting those normalized values as exact quality evidence.

Every property/index retains its own outcome and native evidence. Native unknown-property is labeled unsupported_property while preserving Error class/code; other native rejections, unknown outcomes/timeouts, malformed/decode errors, and a property outside the selected standard datatype profile stay distinct. Missing optional Reliability or a rejected priority array does not imply bad health. Proprietary JCI Enabled, Offline and Status attributes are distinct from standard Out_Of_Service; they are not guessed from it or queried using unverified datatype mappings.

## Bounds and export

The [owned shared-socket receive profile](ipv4-receive-provenance.md) handles the pinned Windows stack's broadcast destination metadata without rewriting it. Raw BVLC Original-Unicast, actual socket and peer stay validated; the physical IP destination remains unavailable.

This profile uses the shared source-pinned `PropertyEvidence` reader extracted from the tested Calendar/Schedule inventory. It sends only owned, unsegmented, single-attempt ReadProperty requests. Direct/routed receive validation pins the original IPv4 peer, local interface/socket identity and NPDU source rather than trusting a mutable route cache. Other native services/observers remain independent. No point writes, priority commands, relinquishing, out-of-service changes, polling, reconnect or retries are added.

There is one active inspection, a 15-second whole-operation deadline including lock acquisition, a 1-second property deadline and 20 ms pacing, 512 requests, 16 points, at most 16 priority slots, 16 KiB encoded values, 4,096 native tags/items and 16 levels, a 64 KiB property-record bound and 2 MiB report budget. Large or segmented values remain unavailable/incomplete. Cancellation, source/interface/configuration change and shutdown retire owned transactions/hooks, retaining completed properties and partially read priority arrays. Cancel-before-admission is bounded and explicit.

Only 16 immutable reports are retained in memory; export before restart or eviction. Receipt times are local UTC and do not resolve a controller clock. Reports include original source/configuration, actual transport candidates, per-property tag re-encoding hashes and a canonical report hash. A matching UDP candidate may still be malformed and does not prove an accepted response. The tag re-encoding hash is explicitly different from original received UDP-byte evidence.

**Export exact point evidence** saves the authenticated HTTP response bytes. Browser JSON previews normalize negative-zero/integral-float spelling; the exported JSON preserves those spellings. Verify `evidence_sha256` by removing only that field, then SHA-256 hashing UTF-8 Python `json.dumps(body, sort_keys=True, separators=(",", ":"), allow_nan=False)`. Source/draft/selected-receipt/navigation changes discard delayed downloads and responses. Restart starts no acquisition, opens no interface and retains no point reports.

## Reviewed scope and evidence

Reviewed sources are [FX-PC PICS, LIT-12011658, 2019-03-22](https://s3.us-east-2.amazonaws.com/buildingcontrolsgroup.media/downloads_1/12011658.PDF), PDF pages 7, 9, 11 and 13 (DOC-2819078f7b2d), and [Field Equipment Controllers PICS, LIT-12011100, 2017-12-01](https://docs.johnsoncontrols.com/bas/r/Metasys/en-US/Field-Equipment-Controllers-Protocol-Implementation-Conformance-Statement), PDF pages 9, 10, 12 and 13 (DOC-8b108370fd38). These distinguish optional reliability/commandable properties and proprietary status fields; they are not proof that a particular connected firmware supports them. The pinned BACpypes3 0.0.110 `object.py`, `basetypes.py`, `primitivedata.py` and constructed-value source provide the exact standard datatype and StatusFlags/quality contracts used here.

Prior behavior remains available: Connect's generic Read property retrieves one value, object pages list IDs, Field trends can summarize quality and use operator metadata, COV retains properties actually notified, and reviewed write safety checks its owned priority slot. The new inspector adds explicit grouped raw evidence without changing those workflows. MF-b3e8f374e9 remains partial beyond this scoped inspector: attaching native quality to every other engineering/test result, proprietary model/firmware mappings, serial/BBMD profiles, persistent point archives and physical sensor/actuator acceptance remain followups. Neither these tests nor a standard reliability code verifies an actual open circuit on the user's equipment.

Validation uses independently authored literal replies over real direct/routed local UDP, API sessions and actual Chromium exports, including malformed native quality, optional native errors, unknown enums, priority Null/signed zero, cancellation and shared Schedule regressions. No site devices or credentials are used.
