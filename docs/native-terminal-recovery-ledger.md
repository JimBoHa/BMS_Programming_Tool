# Recorded terminal recovery lineage in Changes and History

`HIST-NATIVE-TERMINAL-RECOVERY-001` adds a recorded parent-bound terminal summary
and detail section to the existing Changes/History journal. It shows the parent
receipt, analog object/reference, recorded inverse terminals and historical
parent-proof kind/time. **Search recorded terminal parent receipt** uses the
existing local journal filter. The current controller and CAF remain unchanged.

The separate `native-analog-terminal-recovery-recorded/1` metadata profile admits
explicit `native-analog-terminal-recovery-transfer/1` lineage only when its base
profile-2 terminal metadata is valid. It checks the typed origin shape, complete
origin seal, parent/child IDs, current review capture, configuration guard,
object/reference and before/after/inverse terminal relationships. All three
recorded confirmations, unchanged controller identity and the recorded lineage
marker remain required. Unknown or inconsistent explicit evidence stays readable
with unavailable recovery metadata and no parent-search link.

The browser independently checks the closed metadata shape and its relationship
to the admitted terminal movement, child ID and Device instance. Missing or
substituted authority/identity/terminal flags cannot supply a recorded parent
link. The original evidence JSON remains downloadable without reserialization.
Ordinary terminal metadata and older parsers stay separate. A dedicated terminal
lineage section replaces the unrelated generic recovery-unavailable projection
for these explicit records; it does not fall back to another recovery family.

This is recorded evidence, not current recovery admission. Projection reads no
backup archive, resolves no parent binding, calls no preparation/compiler or
controller method and grants no transfer authority. Parent/source availability,
current terminal/wiring state and field acceptance remain unverified. Ordinary
journal enumeration and explicit parent search can still read parent records as
independent local rows. A recorded lineage never promotes an unknown child outcome
to verified or rewrites its immutable attempt/readback evidence.

Checks include actual owned UDP parent/inverse receipts, independent typed and
resealed inconsistent origins, unchanged ordinary records, uncertain outcome
preservation, source/controller lookup sentinels, both graph/CAF entry, desktop/
phone layouts, exact downloads and local parent search. Existing field writers,
compilers, recovery helpers, engineering graphics and styles remain unchanged.
No live-site, VM or Bluetooth operation is part of this scope. General rollback,
broader host/input moves, resources/packages and physical acceptance remain separate;
JCI-10/IO-02 remain partial overall.
