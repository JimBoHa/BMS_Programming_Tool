# Recover a native wire using its verified original output pin

Profile `native-historical-pin-wire-recovery-draft/1` qualifies one previous
connection source when the earlier transfer removed its only outgoing pin from
the current diagram. It uses the actual retained original connection, not a
model/name guess or an arbitrary caller-provided pin. Ordinary observed-pin
editing and the existing v1 recovery profile retain their original behavior.
Broader JCI-10 restore remains partial.

## Operator workflow

1. In **Program → Native backup defaults**, explicitly read a current backup when
   connected. Capture can enter/end backup mode. Inspect the diagram and existing
   connection recorded in the original wire-transfer receipt; choose the saved
   effective source basis and open that receipt.
2. Reconcile an uncertain original attempt through explicit readback first.
   **Prepare previous wire source** uses retained local evidence. If the previous
   source has a current eligible pin, the existing v1 report remains exact. If its
   current pin is missing, this distinct profile requires verified original pin
   evidence and matching current non-default source configuration.
3. Focus moves to the prepared result. Its prior source appears only for this
   qualified recovery, while the replacement selector is locked. The ordinary
   source list and ordinary draft remain separate. **Discard wire recovery
   proposal** restores that draft, including after navigation. Exact proposal
   exports retain their original response bytes. Drafts use the existing bounded
   transient browser cache; they are not a new persistent project format.
4. **Review effective wire compilation** and **Save compiled native wire** produce
   a local source-bound copy with exact review/artifact evidence. They send no
   controller request. Alternatively, use the existing controller transfer review,
   confirm the wire change and interruption, Apply once and verify full readback.
   Saving a local copy never implies a field transfer.

## Qualification and preservation

- The original receipt must be resolved, record possible dispatch and retain a
  verified result or immutable historical verified readback. Reconstruct its
  forward payload from the actual pre-transfer backup and saved settings. Require
  its recorded native payload, tuple, references, configuration and byte width.
- The original effective diagram supplies the actual source object/class,
  connection index, output pin and destination. `native-recorded-wire-pin/1`
  retains these fields and original/current hashes in strict typed evidence.
  Numeric/Boolean aliases and conflicting fields do not qualify.
- The current source must match the recorded original-after expanded application,
  static directory, Device identity and route. The prior source's current
  non-default configuration signature must still match its original signature.
  Changing both source prototypes to the same new configuration does not
  substitute for that original pin proof. Other fresh Real/Boolean defaults and
  saved settings remain current.
- The private compiler includes only that actual original selected connection
  when checking its missing output pin. Its same index excludes it from adjacency
  while the inherited class/configuration/order/cycle/width checks run. An
  original invalid cycle or execution order is not accepted merely because it
  appeared in the old graph. Membership, ports, destination, layout, ordering,
  original source-index width and all other merged bytes remain preserved.
- New review and pre-intent Apply reconstruct the parent/current-source evidence.
  The previous receipt, old token or arbitrary pin metadata cannot authorize a
  new write. Existing fresh capture, application/directory/configuration,
  capacity, credentials, ownership, cancellation, expiry and one-use guards stay.
- Verification requires the full native image, unchanged identity, operational
  state, effective selected wire and other saved values. Lost acknowledgment stays
  uncertain until explicit readback, including after restart. The child retains
  typed pin evidence with its own original backup, allowing independent readback
  if an older ancestor's files become unavailable. This reconstruction is not new
  write admission. No automatic replay or inverse write occurs.

The existing 900-second review, 1,800-second overall operation budget,
four-second individual File bound and preparation interval remain. Direct/routed
IPv4 software peers qualify this operation. No new block/port/wire/I/O allocation,
general compiler, package/resource certification, whole-device restore or physical
controller/BTCVT acceptance is inferred.

## APIs and recorded Changes

The existing `/wire-source/recovery/prepare` route chooses the separately
qualified report. New local copy routes are:

- `POST /api/bacnet/controller/native-application/inspection/historical-wire-source/preview`
- `POST /api/bacnet/controller/native-application/inspection/historical-wire-source/export`

Both require a session token, the exact effective-wire source/proposal and paired
`recovery_parent_receipt` / `recovery_origin_sha256`. Export also requires the
review hash. They reconstruct the original/current proof, create no field plan
or intent and reject caller-supplied pins. Ordinary current-pin copies retain
their existing strict endpoint/schema. The current-pin capability matrix alone
does not grant historical recovery support.

Changes shows recorded original pin/class/backup/hash separately from current
outgoing connections and keeps original dispatch separate from later readback.
It validates only the typed recorded seal and child bindings without loading
source/parent files or authorizing another transfer. Inconsistent metadata stays
unavailable while original receipt evidence remains readable.
