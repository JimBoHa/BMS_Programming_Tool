# Recorded Enum recovery lineage in Changes

**Changes → Recorded changes** and **History → Recorded changes** show a
previous-Enum-code transfer beside its existing native receipt. Open **Details**
to inspect its parent reference, exact numeric proposal, native class/property,
current/proposed and historical encodings, captured storage, state-metadata
fingerprint and historical verification proof. **Search recorded parent receipt**
searches local recorded references; it does not query a controller or establish
that the parent or its original files are still available.

This projection is `native-enum-recovery-recorded/1`, limited to the known
`native-enum-default-recovery-draft/1` origin and
`native-effective-enum-default-transfer/1` child operation. It validates the
recorded origin seal and the child's exact review capture/snapshot, unchanged
vendor 5 Device identity/name, record, class 528/529, property 3113, strict
unsigned16 codes, actual native tags, selected encoding fingerprint, captured
fixed Enum storage and encoded state metadata. Both recorded transfer
confirmations and the compilation/payload bindings must agree. Unknown,
incomplete, conflicting or authority-looking origin fields produce an unavailable
lineage marker while retaining the original receipt and every other history row.

The metadata records a proposal, independently of its dispatch and latest
readback. A later verified observation does not rewrite whether the original
attempt entered dispatch. Parent verification can be an original result or an
immutable historical readback event. Equal numeric codes can have different
native widths: a historical one-byte zero and a proposed retained two-byte zero
remain distinct encodings in the evidence. Explicit absence of state metadata
remains absence; the numeric storage bound does not invent allowed states or
their meanings.

The browser independently validates the known projection shape, exact row and
Device context, typed codes/tag widths, storage bounds, explicit state evidence,
bounded proof digests/time and fixed scope before rendering it. It does not
revalidate the origin seal against a parent journal or source files. The server
checks the recorded origin and child bindings locally. Neither layer asserts
present source availability or current live state. Malformed metadata cannot
supply a parent-search action or become a controller permission.

This feature adds no endpoint, controller request, backup load, parent-journal
lookup, compilation, restore, retry or Apply/undo action. The existing token-
admitted local `/api/changes/query`, source filters, station/route/interface
filters, pagination and exact original receipt download remain in place.
Opening native Program tools keeps the current workspace target. Actual recovery
still requires the [separate preparation and new confirmed transfer](native-enum-default-recovery.md).

Qualification covers literal class 528/529 values and actual authored native
recovery receipts, strict malformed origin/child bindings, explicit state
absence, historical readback proofs, original dispatch versus later observations,
missing originals and offline restart. Projection tests prohibit controller
operations and original-source/parent-proof reads. Chromium/WebKit cover graph
and CAF entry, Changes and History, recorded direct/routed targets, phone layout,
exact original JSON, missing references, substituted code/encoding replies and
late parent-query retirement. Existing Changes/History input, point-name and
recovery-family workflows remain covered. No styles are changed. These are local
software checks; no site, VM, Bluetooth, CCT reopening, manufacturer compiler
oracle or physical controller acceptance is established. General native
compilation and Enum semantics remain separate.
