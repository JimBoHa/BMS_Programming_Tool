# Recorded configured binary recovery lineage

`UI-NATIVE-BINARY-TERMINAL-RECOVERY-LEDGER-001` presents original receipt, recorded
binary input/reference, inverse terminal pair and historical verification inside
existing Changes and History. The operator can search the parent locally, inspect
recorded evidence and download the unchanged child receipt.

The backend projects only the child's retained intent. Its separate closed profile
requires the binary recovery namespace, typed sealed origin and independently valid
binary terminal metadata. Child, original and selected-capture identifiers, route,
instance, object/reference, terminal pair and configuration guard must agree.
Malformed, incomplete, mixed or unsupported lineage yields unavailable metadata.
A binary recovery namespace cannot fall back to an older operation family.

Counter values are historical child observations. Optional counters and polarity
remain absent when not recorded. The origin contains no parent counter map, so this
projection does not assert parent/current counter equality or look up those values.
The browser independently verifies the closed record/origin shapes, typed child
metadata and Python-compatible origin seal using the already pinned synchronous
hash implementation. Field-transfer cryptography remains unchanged.

Valid parent search is an explicit local filter. Opening input tools keeps the
current graph/CAF/controller context and starts fresh selection; it does not stage
a recovery proposal. Invalid lineage supplies neither parent nor tool links, even
when earlier input, recovery, point-name or connection metadata is injected. Original
evidence and recorded outcomes remain available.

Opening or projecting a record performs no parent/source lookup, compilation,
controller query or write. Recorded lineage grants no transfer authority and does
not promote an uncertain outcome to verified. Current source, configuration and
physical wiring require their own workflows.

Verification covers actual retained verified and uncertain owned-UDP children across
restart, removed original/source evidence, forbidden lookup/compiler/controller
paths, unchanged downloads/status, typed/optional counters and malformed or resealed
lineage. Browser coverage includes independent seal admission, older-family fallback
refusal, desktop/phone Changes/History, local parent search and graph/CAF context.
Earlier ledger projections retain their own contracts. No private site inventory
or live-site operation is used.
