# Local effective Enum default compiler

In **Program → Native backup defaults**, select and inspect a retained backup.
Open an actual class 528/529 Enum record, choose **Enum default source → Merge
retained saved settings**, then **Open saved Enum defaults**. The editor shows
the original archive code separately from the merged saved code and any captured
fixed numeric storage capacity. Review a proposal, save its exact review JSON or
**Save effective Enum copy**.

This mode requires an identity-verified retained vendor-5 snapshot. Native root
instance/name/model must match that recorded acquisition, all original Files
3/11/12 must still match their hashes and the saved directory/storage must pass
the existing selector, datatype, range, coverage and CRC checks. Captured serial
metadata does not prevent local compilation. This does not verify a current
controller or query live settings. Unknown saved formats or identity mismatches
leave original-archive editing and its unfinished drafts available separately.

The local profile is `native-effective-enum-default-compiler/1`. The compiler
merges retained saved values into File 3, then edits one existing class 528/529
Enumerated Default Value (3113). Original/effective Enum field membership,
references and native IDs must agree; root identity stays unchanged. A merge
that introduces another supported Enum field is outside this profile. Unknown
application/saved structures retain the existing parser's refusal behavior.

Captured fixed saved storage kind 9 contains two payload bytes. When that actual
selected slot exists, the compiler bounds the proposal to 0–65535. Without a
fixed selected slot, only the local unsigned32 representation is checked. This
is recorded numeric capacity, not a controller-model inventory, manufacturer
state table or allowed-code guarantee. Code membership, state meanings,
executable mappings, reliability/restart behavior and package compatibility remain
unverified. Captured state metadata is preserved without interpreting its labels
or numbers as portable bindings.

The native Enum writer retains its supported framing/width rules and independently
reparses and checks every unrelated merged native byte. Other merged settings,
unknown records and metadata stay intact. Selecting the already effective value
returns the merged application, which can differ from the original archive when
other saved settings differ. All three original backup files remain unchanged.
This does not update saved files, allocate blocks, generate general logic, enable
an Enum field transfer by itself or establish CCT/physical acceptance. The separate
[Enum transfer workflow](native-enum-default-transfer.md) additionally requires an
actual selected fixed slot, exact native IPv4 station, fresh preflight, one-use
review, confirmations and full readback.

Token-admitted local `POST /api/bacnet/controller/native-application/enum-default-compiler/`
operations are `source`, `preview` and `export`. Source and review identify the
original/effective hashes, full snapshot, route, files and captured parameter merge.
Preview binds the original source, exact merged property fingerprint and strict
integer proposal. Export recomputes that review, then returns artifact/review/
snapshot SHA-256 headers. No controller query, credential, transfer plan or
transfer-journal entry is created. The nested selected-edit profile operates on
the already merged File 3; its raw writer does not perform a second saved merge.

The browser independently checks source/merge/file/route/field/storage evidence
and operation flags, then verifies review bindings and actual downloaded bytes.
Archive and effective raw proposals have separate source-specific memory caches;
each refuses new work at its existing 128-field bound without eviction. Invalid
or empty text remains intact. Explicit discard releases its own draft. Mode,
source, lifecycle and edit changes retire effective reviews and late responses;
no saved proposal restores field authority. These caches do not promise recovery
after closing or reloading the application.

Local qualification uses independently authored fixed Enum slots and literal
native tags, complete plain/gzip sources, actual saved-setting differences,
capacity boundaries, no fixed slot, no selected change, wrong datatypes/CRCs,
identity mismatches, changed originals and token-admitted HTTP with field methods
forbidden. Browser checks exercise both local entry paths, raw/effective draft
separation, phone layout/focus, source/review/artifact substitutions and delayed
replies. These establish the software profile, not manufacturer compiler or
physical acceptance. The [native-backup operation table](native-backup-operation-capabilities.md)
separately qualifies this effective compiler from the actual retained identity,
saved merge and eligible fields. Its captured-storage counts remain numeric
representation evidence and prepare no Enum field transfer.
