# Native Enum default controller transfer

In **Program → Native backup defaults**, inspect a backup from the selected
controller, open an actual class 528/529 Enum record and choose **Merge retained
saved settings**. Open the saved defaults and enter the intended numeric code.
The existing **Controller transfer** panel provides a separate **Review
controller default transfer → Apply native default to controller → Read back**
workflow. Local review/save remains available separately.

This is `native-effective-enum-default-transfer/1`, limited to one existing
Enumerated Default Value 3113 with an actual selected datatype 9 fixed saved
slot. The recorded two-byte numeric capacity bounds proposals to 0–65535.
A source without that selected slot can still qualify the local UInt32 compiler;
it cannot prepare this transfer. No model name supplies missing storage or
allowed states. Code membership and state meanings remain unverified. The
operator must confirm the exact selected controller/code and its intended meaning
separately from confirming the application transfer and control interruption.

The adapter requires the exact plain direct or explicitly routed BACnet/IPv4
interface, station and retained vendor 5 identity. Native family credentials
remain local. Serial, Bluetooth and foreign-device native transfer are outside
this profile. Interface-open, a local compiled copy and this operation's
source-qualified/preflight-required capability row are not prepared field intent.

Review binds the complete source snapshot, original archive hash, selected
record/property encoding, effective prior code, proposed strict integer,
captured storage and encoded state metadata (property 931, or explicit absence).
That fingerprint does not interpret state meanings. Apply consumes that one-use
review and checks its operation
profile, target/interface, ownership, credentials and expiry. It obtains fresh
Files 3/11/12: original application/directory and selected effective code/fingerprint
must still match, including the selected state metadata, while other fresh saved
values are merged. The final payload
can therefore differ from preview. The existing capacity and omitted-application-
field qualification remain required.

The original backup, final payload and durable intent exist before the first
restore request. One application restore writes only File 3; Files 11/12 are read,
not uploaded. Backup and readback can enter/end backup mode. Apply can interrupt
controller operation. No Device instance, name, block, I/O allocation, wire or
supervisor configuration is changed by this profile.

Verification requires the full expanded native image to equal the reviewed edit
of the fresh merged source, unchanged Device identity and a matching effective
saved Enum code and state metadata fingerprint. The native writer retains an
existing value width while the
saved-value serializer uses a minimal width. Equal selected Enumerated codes
can consequently have different encodings, such as two-byte versus one-byte
code 0. Only after complete image equality and strict selected archive/effective
code/datatype checks does the Enum-specific adapter exclude that exact native
class/instance/property tuple from other-setting classification. Both encoding
fingerprints and the equal typed code proof remain recorded. Every other saved
setting passes the unchanged runtime-output classifier. Wrong selected codes,
other changed settings, invalid saved CRC/type and changed native bytes cannot
become verified results.

Acknowledgement alone does not establish verification. Lost acknowledgements,
cancellation after dispatch, unavailable readback or mismatches retain an
unresolved receipt and block another write. Readback/reconciliation after restart
does not replay the application. The original journal and exact review/receipt
downloads remain available. [Previous-Enum-value recovery](native-enum-default-recovery.md)
is a separately qualified local proposal and new confirmed transfer; this profile
adds no automatic rollback or inverse write.

The browser independently checks source/identity, strict numeric codes and native
tags, captured capacity, saved merge, omitted-field qualification, one-use review,
fresh compilation receipt and verified preservation bindings. It allows other
fresh saved settings to change the final payload without changing the selected
edit. Invalid raw text remains a local draft. Source or target changes retire
reviews; controls/navigation lock during a field operation. **Stop native
operation** retires the local review before requesting cancellation, so a held
reply cannot restore that review. Dispatched uncertainty still retains its result.

Token-admitted native application endpoints are `POST
/api/bacnet/controller/native-application/enum-default/transfer/preview` and
`.../apply`; the existing native `readback`, `cancel`, `status`, original backup
and exact receipt endpoints remain shared. Preview accepts strict source/field/
integer/target parameters, not labels, Boolean coercions, identity allocation or
unpaired recovery authority. Paired parent/origin hashes require the separate
recovery qualification above. Apply uses the existing two explicit strict confirmations.
Changes lists the recorded operation as **Native Enum code transfer** with its
record reference; that read-only projection performs no controller request.

Qualification uses literal authored Enum slots/tags and isolated direct/routed
UDP peers. It covers both classes, compressed/plain images, code 0/65535,
retained/consumed saved slots, fresh unrelated settings, stale selected values,
wrong storage/source/profile/credentials/capacity, one-use intent, durable
pre-dispatch evidence, cancellation, acknowledgement loss and restart readback.
Browser checks cover connected and CAF entry, phone layout, exact route and
review/receipt bytes, source/navigation locking, invalid drafts, altered replies,
Stop retirement and recovery of an original retained receipt. These establish
software protocol behavior. No site, Bluetooth, CCT reopening, manufacturer
compiler oracle, allowed-state table or physical acceptance is established.
JCI-03/JCI-05/JCI-09/JCI-10 remain partial overall.
