# Local CAF constant creation from recorded configuration

`FMT-CAF-CONSTANT-COPY-001` adds one unconnected Float Constant to an existing
version 1.0 CAF activity/sequence. It copies an actual class-551 prototype and its
required class-527 output child. Both receive fresh local identities and exact
hierarchical references. The graph gains one member, an execution entry directly
after the prototype and a position copied from the prototype's recorded layout
shape. The operator supplies finite Float32 X/Y text; its spelling is retained.
The opaque third layout field is copied without inventing its meaning.

The parent constant retains its four-property schema, exposed property 85 and
recorded standard-name code (11 or 796 in this profile). The child retains one of
five observed scalar schemas, including its optional recorded numeric value,
units/name/Boolean metadata. An omitted value stays omitted. Creating the block
does not introduce a guessed numeric default, enum meaning or port identifier.
To change a copied output's existing value, open the exported CAF and use the
existing supported scalar workflow. Wiring the new member is a separate guarded
CAF connection export using an actual compatible connection prototype.

## Local creation and preservation contract

Allocation scans all actual object IDs and every typed BACoid reference, including
unresolved references. It selects two consecutive positive IDs above their
maximum, within this profile's 22-bit ceiling. It refuses noncanonical/out-of-range
IDs, exhaustion, unsupported XML framing/root bookkeeping, extra descendants,
unknown constant/output schemas, incoherent identities or incoming prototype
connections. A recorded parent user-modified flag must already be true when
present; no undocumented flag transition is manufactured. Existing archive/XML,
element/depth and unsigned-short graph limits still apply.

Only the two new object identities and graph membership/order/layout additions
are generated. All original objects except that parent graph remain byte exact.
Every unrelated parent property, including wires, continuation data and opaque
selection/state bookkeeping, remains exact. Cloned nonidentity configuration
retains its lexical bytes. The existing CAF ZIP helper preserves original entry
attributes (including zero), dates, comments and archive comments. Changed ZIP
compression and raw container bytes are not claimed identical. Independent
parsing verifies the expected graph, new identities, child shape and unchanged
records before an export is offered.

Three strict token-protected offline routes live at
`/api/caf/{id}/constant-copy/source`, `/preview` and `/export`. They bind the
opened archive SHA, actual diagram/prototype/child hashes, membership, execution
order, derived identities and proposed coordinates. Separate selection, creation
and review seals bind the deterministic output. Export recomputes the current
proposal and returns artifact/review/source/creation proof headers. There is no
Apply route, field query, field write, native application transfer or field plan.
Local reviews are reusable local export evidence, not one-use controller plans.

## Existing Program workflow

Open a CAF file, select **Program → CAF file → Logic**, then expand **Copy a
recorded Float Constant**. Inspect an actual prototype, enter the new position,
review and save a separate CAF copy. **Save exact constant review** preserves the
admitted original response bytes. The client checks the selection and nested
review seals, exact clicked proposal, four proof headers and actual artifact SHA
before saving. This copy uses the opened original; other pending edits are not
implicitly merged. The ordinary top-level CAF Save snapshot contract is unchanged.

Up to 32 source/diagram/prototype draft contexts retain exact unfinished position
text across task and file navigation. Passive inspection consumes no slot. A full
cache refuses new work without evicting an older draft; explicit discard frees
only that context. Reviews/downloads retire on source, prototype, controller
context, task, lifecycle and visibility changes, including ABA navigation. Local
drafts remain. Saving marks only the matching clicked draft as saved. Drafts are
in memory; no reload persistence or restored controller authority is implied.
Controls retain the established teal interface, compact navigation, readable
labels, keyboard access and engineering layout. No destination or tile is added.

## Qualification and remaining scope

All 121 actual constant/output pairs in seven authorized, undistributed local
CAFs were copied and independently read back in memory. Original files stayed
unchanged; no derived private CAF was saved or committed. Authored examples test
exact expected XML, both graph classes, standard-name variants, optional output
schemas, numeric omission, repeated creation, ID allocation above unresolved
references, single-quoted XML, recorded namespace declarations, exact ZIP metadata
and subsequent connection creation through the original guarded API.

Source and installed-package checks separately exercise strict HTTP admission,
browser artifact/review proof, unfinished drafts, source/prototype ABA, late
results, failed responses and phone/keyboard interaction. The delivery's local
qualification report records exact case counts, prior failures, clean-wheel
module/asset parity, distribution checks and original-checkout preservation.

This is a local structural-copy profile. It does not verify a vendor allocator,
reserved IDs, memory/scan resources, new hardware or terminals, arbitrary block
semantics, native File-3 generation, CCT reopening, firmware execution, physical
transfer or BTCVT. General graph `new_object_creation`, compiler and download
capability flags remain false: they describe the broader unsupported operation.
The explicit source endpoint qualifies only this narrow recorded profile.
JCI-02, JCI-03, JCI-06 and JCI-09 remain partial.
