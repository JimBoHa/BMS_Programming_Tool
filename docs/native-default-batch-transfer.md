# Typed native default batch transfer

**Program → Native backup defaults → Compile several native defaults together →
Transfer default batch to controller** applies one to sixteen distinct existing
Real (526/527), Boolean (530/531) or Enum (528/529) Default Values, property 3113,
through one guarded native File 3 restore. It reuses the selected controller,
complete route and interface. There is no model-selected inventory or new global
destination. The profile is `native-effective-default-batch-transfer/1`.

Local compilation, unfinished draft files and saving native copies remain useful
offline. They grant no field authority. Field review requires an open plain
BACnet/IPv4 interface, exact direct or explicit IPv4-router/DNET/station target,
vendor-5 identity-qualified original Files 3/11/12, native backup/restore
credentials and no conflicting owned operation. Every selected Enum must have
its actual captured fixed unsigned 16-bit saved slot. Numeric capacity does not
establish an Enum code's meaning.

## Edit, review, apply, verify

1. Capture and open the intended controller's original native backup. Capture
   enters and ends backup mode. Select recorded fields and enter typed values.
2. **Review default batch transfer** binds the original manifest, source files,
   effective values, native encodings, types and selected Enum storage/state
   metadata to the exact controller identity and route. At least one value must
   change. The independent typed compilers and both composition orders must agree
   on the same literal output, preserving every unselected native byte.
3. Confirm all selected values, Enum meanings and possible control interruption.
   **Apply default batch to controller** consumes that review once, captures fresh
   Files 3/11/12 and rechecks identity, capacity, selected guards and source/static
   directory hashes. Other fresh saved values are merged, so the final payload
   can differ from preview. The durable intent and original backup precede the
   first restore command. Restore commands and blocks are never automatically
   retried after a lost acknowledgement.
4. Full native application and saved-setting readback must verify every selected
   value and complete application preservation. Fixed Enum saved rows may be
   consumed or compacted after a restore; the native bytes, effective code and
   state metadata must still match. Old saved values cannot count as success.
5. Retain the exact review and receipt exports. An uncertain outcome blocks
   another native engineering operation. Load the original retained receipt and
   use **Read back default batch** on its original controller/interface. This
   performs no restore replay and works after a server restart. Recovery of the
   original application is reported separately from verification of the proposal.

Draft, source, route, task, visibility and page lifecycle changes retire review
authority, including coalesced away-and-back events. Active transfers lock task
switches and navigation; late outcomes remain attached to the original operation.
Changes and History show bounded recorded typed proposals without rereading
private source files or contacting the controller. Historical records confer no
transfer authority.

## Scope

This is one native application restore for selected defaults, not a general
multi-operation transaction. Device identity, graph, blocks, wiring, hardware
assignments and unrelated application bytes are preserved. General native
authoring, resources/packages, firmware execution, CCT comparison, unrestricted
cross-brand conversion, previous-value batch recovery authoring, serial/BBMD/
Bluetooth transfer and physical controller acceptance remain separate work.
Qualification uses authored localhost BACnet peers and independently installed
distribution assets; it does not establish field or BTCVT acceptance.


A separate opt-in [source prerequisite analysis](native-batch-transfer-capabilities.md)
adds profile21 evidence without changing this workflow's original contract or
creating controller authority.
