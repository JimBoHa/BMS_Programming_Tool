# Recorded binary terminal moves in Changes and History

`HIST-NATIVE-BINARY-TERMINAL-001` adds a separate closed projection for recorded
binary input transfer profile 3. Older analog metadata and recovery remain separate.
The existing Changes and History views show the binary object, previous and new
UI terminal, exact native reference, recorded confirmations, preserved state text,
state index and optional polarity. Captured COS Count and Elapsed Active Time are
explicitly historical values, never current live measurements.

The backend validates the recorded operation, compiler and sealed inner copy,
identity, typed confirmations, configuration guard, source/merge/output hashes,
record counts and exact two nonoverlapping fixed-width payload changes. Unsupported
versions, inconsistent bindings or malformed values keep the original evidence
without structured binary metadata. No original backup is reopened, compiler
instantiated or controller queried to list these records.

The browser independently admits the closed metadata shape and types. Explicit
binary metadata takes precedence over supplied legacy analog metadata, including
when the binary metadata is unavailable. Valid records may open the existing local
input tools without replacing the current controller, route or CAF. They create no
write plan or transfer authority. Recorded confirmations do not verify current
physical wiring. Original evidence downloads preserve the endpoint response bytes.
The journal outcome remains independent: readable metadata never promotes an
uncertain transfer to verified.

Verification uses authored loopback protocol peers, persisted real transfer
receipts, restart with failing source/compiler/field sentinels, malformed sealed
records, independent browser admission, Changes and History, both entry paths,
compact layout, local navigation, exact evidence downloads and injected fallback
rejection. No site, VM or Bluetooth acceptance is claimed.

Next: source-specific binary capability witnesses, followed by further host-specific
reassignment. Binary allocation and electrical changes, SA/IOM/cross-host movement,
resources/packages, general native compilation and CCT/physical/BTCVT acceptance
remain separate work.
